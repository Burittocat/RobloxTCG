# RobloxTCG

로블록스 스튜디오용 트레이딩 카드 게임. 현재 **룰 엔진 코어**까지 완성되어 있고,
Studio 없이 돌아가는 테스트 75개가 전부 통과한다.

---

## 시작하기

```powershell
aftman install          # rojo 7.7.0 + lune 0.10.4
lune run tests/run.luau # 룰 엔진 테스트 (75개)
rojo serve              # Studio 의 Rojo 플러그인에서 Connect
```

Studio 를 바로 열어보려면 `rojo build --output build.rbxlx` 로 나온 `build.rbxlx` 를 열면 된다.
서버가 부팅되면 출력창에 `[TCG] 연기 테스트 통과 — 룰 엔진 정상` 이 찍힌다.

---

## 폴더 구조

```
src/shared/Rules/        ← 룰 엔진. Roblox API 를 전혀 쓰지 않는 순수 Luau
  Enums.luau             카드종류 · 키워드 · 존 · 페이즈 · 효과종류
  Config.luau            모든 룰 상수 (★ = 기획서 미확정 항목, 아래 참조)
  RNG.luau               결정론적 난수 (같은 시드 → 같은 셔플. 세이브/리플레이용)
  CardDef.luau           카드 스키마 검증 + 덱 검증
  Registry.luau          카드 id → 정의 조회
  Keywords.luau          인스턴스의 현재 키워드/스탯 (버프 포함)
  GameState.luau         상태 생성 · 존 이동 · 드로우 · 라이프 · 직렬화
  Combat.luau            공격/방어 합법성 + 데미지 해결  ← 태그 규칙의 핵심
  Phases.luau            페이즈 상태머신 + 페이즈별 권한
  Effects.luau           마법 효과 해석 (카드는 코드가 아니라 데이터)
  Stack.luau             시전/소환 스택 (즉시시전 대응)
  init.luau              외부에 노출되는 액션 API

src/shared/Cards/        ← 카드 DB. Core.luau 에 초기 19장
src/server/              ← 부팅 + 연기 테스트 (매칭/매치러너는 다음 단계)
src/client/              ← 자리표시자 (UI 는 다음 단계)
tests/                   ← Lune 테스트. lib/RobloxEnv.luau 가 Roblox 트리를 흉내낸다
```

### 왜 Roblox 코드를 Studio 없이 테스트할 수 있는가

`tests/lib/RobloxEnv.luau` 가 `src/shared` 디렉터리를 읽어 Instance 비슷한 노드 트리를
만들고, `script` 와 `require` 를 주입한 환경에서 각 모듈을 실행한다.
**룰 엔진 코드에는 테스트를 위한 변환이나 분기가 한 줄도 없다** — Rojo 가 Studio 로
밀어넣는 파일과 테스트가 검증하는 파일이 바이트 단위로 같다.

## 구현된 룰

### 턴 구조 (기획서 그대로)

```
Untap  → 턴 플레이어의 모든 카드 언탭, 코스트 소환 횟수 리셋   (자동)
Draw   → 1장 드로우 (선공 1턴은 생략)                          (자동)
Main   → 코스트 소환 · 생물 소환 · 마법 시전  / 상대는 즉시시전만
AttackPrep  → 공격자 선언
DefensePrep → 수비측: 방어 배정 · 소환(탭) · 마법
Combat → 데미지 동시 해결                                       (자동)
EndTurn→ 생물 피해·버프 정리 → 다음 턴                          (자동)
```

공격자가 하나도 없으면 `DefensePrep` / `Combat` 은 자동으로 건너뛴다.

### 태그 5종

| 태그 | 구현 |
|---|---|
| **신속** | 소환한 턴에 바로 공격 가능. 수비준비 페이즈에서 **언탭**으로 등장해 즉시 방어 가능 |
| **비행** | 지상(비행X) 비원거리 생물은 비행을 **공격도 방어도** 못 함 |
| **도발** | 필드에 있으면 상대는 플레이어를 직접 공격 불가. 비행도 못 무시함 |
| **원거리** | 비행을 공격/방어 가능, 도발 무시. 대신 플레이어 직공 데미지 **절반(내림)** |
| **즉시시전** | 상대 메인 / 본인 메인 / 본인 수비준비에 발동. 스택 위 소환·마법을 무효화하거나 덱으로 되돌림 |

### 코스트

- 덱 60장 중 원하는 만큼 코스트 카드. 턴당 1장 필드에 소환.
- 코스트 카드는 **언탭 상태로 등장**해 그 턴 바로 탭해서 쓸 수 있고, 다음 자기 언탭 스텝까지 언탭되지 않는다.
- 생물/마법을 낼 때 언탭된 코스트 카드가 순서대로 탭되며 지불된다.

### 스택 (즉시시전이 동작하는 방식)

카드를 내면 즉시 효과가 나지 않고 스택에 올라간다 → 상대에게 대응 창이 열린다 →
아무도 대응하지 않으면 해결된다. 그래서 "상대가 소환하려는 생물을 덱으로 되돌리기",
"상대 마법 무효화"가 성립한다. **무효화당해도 지불한 코스트는 환불되지 않는다.**

## ★ 기획서에서 확정이 필요한 항목

임의로 정하고 진행했다. **전부 `src/shared/Rules/Config.luau` 한 파일에서 바꿀 수 있다.**
바꿔도 테스트는 대부분 Config 값을 읽도록 짜여 있어 그대로 통과한다.

| # | 항목 | 현재 값 | 근거 / 대안 |
|---|---|---|---|
| 1 | 비행끼리 서로 방어 | **가능** (`flyingCanBlockFlying=true`) | 기획서 문자 그대로면 원거리만 비행을 막을 수 있어 비행이 사실상 무적이 된다. `false` 로 바꾸면 원문 그대로 |
| 2 | 원거리 직공 반올림 | **내림** (4→2, 5→2) | `"ceil"` 로 바꾸면 5→3 |
| 3 | 선공 1턴 드로우 | **생략** | 안 그러면 선공이 카드 우위 + 템포 우위를 동시에 가진다 |
| 4 | 같은 카드 최대 매수 | **4장** (코스트 카드 제외) | 기획서에 언급 없음 |
| 5 | 공격 선언 시 공격자 탭 | **탭됨** | 안 그러면 공격 후에도 방어가 가능해 탭이 자원 개념으로 기능하지 않는다 |
| 6 | 공격자 1명당 방어자 수 | **1명** | 다중 방어를 열려면 데미지 배분 순서 입력이 추가로 필요하다 |
| 7 | 공격준비 페이즈 상대 즉시시전 | **허용** | 기획서에 창이 없으면 "공격 선언에 대응"이 불가능해진다 |
| 8 | 수비준비 페이즈 **공격측** 행동 | **불가** | 기획서상 즉시시전 창은 "상대 메인/본인 메인/본인 수비"뿐 → 방어측이 마지막 발언권 |
| 9 | 생물 직접 겨냥 시 반격 | **탭된 생물도 반격** | 순수 트레이드. `false` 면 "탭시키고 잡아먹기"가 강해진다 |
| 10 | 빈 덱 드로우 | **패배** | 기획서에 없음 |
| 11 | 손패 상한 | **무제한** | 기획서에 없음 |
| 12 | 수비준비에 코스트 카드 소환 | **불가** | "1턴당 한 번"이 자기 턴 기준인지 불명확 |

### 기획서 내부 모순 하나

신속 설명에 **"수비 페이즈에서 탭하여 소환할 수 있다"** 와,
수비준비 페이즈 설명에 **"신속 태그가 적용된 생물만 언탭하여 소환할 수 있다"** 가
서로 반대다. 후자(신속 = 언탭 등장 = 즉시 방어 가능)를 채택했다 —
그래야 "신속 = 즉시 행동"이라는 태그의 정체성이 일관된다.

## 다음 단계

기획서 순서(로비 → 매칭 → 로딩/메뉴 → 카드·덱·드로우 → 전투 → 캠페인 세이브) 기준으로,
**카드·덱·드로우 시스템과 핵심 전투 시스템의 서버측 로직은 이미 끝났다.** 남은 것:

1. **매치 러너 + 네트워크** — RemoteEvent 배선, 액션 검증, `Rules.viewFor` 로 상대 손패 숨기기
2. **덱 빌더 + 저장** — DataStore, 60장/4장 제한은 `CardDef.validateDeck` 이 이미 처리
3. **전투 UI** — `Rules.canPlayCard` / `Combat.legalAttackTargets` / `Phases.permissions` 를
   그대로 불러 버튼을 켜고 끄면 서버 판정과 절대 어긋나지 않는다
4. **로비 + 매칭** — MatchmakingService 또는 자체 큐
5. **PvE 캠페인** — `GameState.serialize/deserialize` + 결정론적 RNG 가 이미 준비됨. AI 만 붙이면 된다
6. **BM** — 카드팩(RNG 재사용), 테두리/스킨/이펙트는 카드 데이터와 분리된 코스메틱 레이어로
