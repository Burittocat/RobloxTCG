# RobloxTCG

로블록스 스튜디오용 트레이딩 카드 게임. **룰 엔진 · PvE AI · 전투 UI · 빠른 대전 매칭**까지
동작하고, Studio 없이 돌아가는 테스트 152개가 전부 통과한다.
소스는 전부 `.luau` 파일이라 VS Code 에서 고치고 Rojo 로 Studio 에 밀어넣는다.

로비는 없다. 접속하면 버튼 두 개짜리 시작 화면이 뜨고, **빠른 대전**을 누르면
서버를 넘나드는 큐에 서서 사람을 찾는다 (유희왕 마스터듀얼 · MTG 아레나 방식).

---

## 1. Studio 에서 바로 플레이하기

처음 한 번만:

```powershell
aftman install          # rojo 7.7.0 + lune 0.10.4 설치
lune setup              # 에디터용 Lune 타입 정의 (tests/ 의 @lune/* 를 알아보게 한다)
```

플레이스 파일을 만들어 여는 방법 (가장 빠름):

```powershell
scripts\studio.cmd      # 검사를 전부 돌린 뒤 Studio 로 연다
```

**확장자 `.cmd` 까지 붙여서** 부른다. 이유가 둘이다.

- 윈도우의 기본 실행 정책이 `Restricted` 라 `.\scripts\studio.ps1` 은
  "스크립트를 실행할 수 없으므로" 로 막힌다. `.cmd` 가 이번 실행에만 Bypass 를 주고
  `.ps1` 을 부르므로 컴퓨터 설정을 바꾸지 않아도 된다.
- 확장자를 빼고 `scripts\studio` 라고만 치면 **PowerShell 이 `.cmd` 가 아니라 `.ps1` 을
  먼저 고른다.** 그러면 위의 실행 정책에 그대로 막힌다.

`scripts/` 안의 윈도우 스크립트는 인코딩 규칙이 나머지와 다르다. `.gitattributes` 가
못 박아두고 있으니 새로 만들 때 맞춰야 한다.

| | 인코딩 | 줄바꿈 | 왜 |
|---|---|---|---|
| `*.cmd` | **ASCII 만** | CRLF | cmd.exe 는 OEM 코드페이지로 읽고 CRLF 를 요구한다. 한글 주석을 넣으면 깨지면서 그 줄을 명령으로 실행하려 든다 |
| `*.ps1` | **UTF-8 + BOM** | CRLF | Windows PowerShell 5.1 은 BOM 이 없으면 CP949 로 읽는다. 한글이 깨지며 따옴표가 어긋나 파일 전체가 파싱 실패한다 |
| `*.sh` · `*.luau` | UTF-8 (BOM 없이) | LF | sh 와 Lune 은 BOM 을 문법 오류로 본다 |

검사를 건너뛰고 바로 열려면:

```powershell
rojo build --output build.rbxlx
start build.rbxlx       # Studio 가 열린다 → F5(Play)
```

`start` 가 "이 파일을 어떻게 열까요" 를 물으면 `.rbxlx` 파일 연결이 없는 것이다.
`studio.ps1` 은 그 경우에도 되도록 Studio 실행 파일을 직접 찾아서 넘긴다.

검사를 먼저 돌리는 편이 결국 빠르다 — Studio 는 스크립트가 죽어도 게임을 계속 돌리므로,
출력창을 안 보고 있으면 "왜 버튼이 안 먹지" 를 화면만 보며 한참 헤매게 된다.

> **Studio 에서 저장하지 말 것.** `build.rbxlx` 는 `rojo build` 가 만드는 산출물이다.
> Studio 에서 `Ctrl+S` 를 누르면 그 파일을 Studio 가 저장한 버전으로 덮어쓰고, 그 창에서
> 그대로 게시하면 **그때 열려 있던 낡은 코드가 올라간다.** (Studio 가 저장한 파일은
> 지형·카메라 같은 걸 덧붙여서 rojo 산출물보다 눈에 띄게 커진다 — 구분하는 단서다)
> 고친 걸 반영하려면 창을 닫고 `scripts\studio.cmd` 를 다시 돌린다.

VS Code 에서 고치면서 Studio 에 실시간 반영하는 방법 (개발할 때 이쪽):

```powershell
rojo serve              # 터미널에 남겨둔다
```

그다음 Studio 에서 플러그인 툴바의 **Rojo → Connect**. 이후 파일을 저장할 때마다
Studio 트리가 갱신된다.

F5 를 누르면 **시작 화면**이 뜬다.

| 버튼 | 하는 일 |
|---|---|
| **빠른 대전** | 큐에 서서 사람을 찾는다. 찾으면 대전 서버로 옮겨져 한 판이 시작된다 |
| **AI 연습** | 큐를 타지 않고 이 서버에서 바로 AI 와 한 판 |

혼자 테스트할 때는 **AI 연습**이 빠르다. 매칭까지 확인하려면 Studio 의 테스트 탭에서
플레이어 수를 **2명**으로 놓고 시작한 뒤, 두 창에서 각각 빠른 대전을 누른다
(Studio 는 텔레포트가 안 되므로 같은 서버 안에서 붙는다 — 아래 '매칭' 참조).

전투 조작은 전부 마우스다.

| 상황 | 할 일 |
|---|---|
| 메인 페이즈 | 손패 카드를 클릭 → 코스트/생물/마법이 나간다 |
| 대상이 필요한 마법 | 초록 테두리가 켜진 생물·플레이어·스택 항목을 클릭 |
| 공격준비 | 내 생물 클릭 → 공격할 대상 클릭 |
| 수비준비 | 내 생물 클릭 → 막을 공격자 클릭 |
| 상대가 뭔가 시전 | `대응 패스` 또는 '즉시시전' 마법으로 응수 |

`E` 페이즈 종료 · `P` 대응 패스 · `Esc` 선택 취소 · `L` 로그 ·
`R` 새 판(AI 연습이 끝난 뒤에만. PvP 는 매칭을 다시 타야 한다).

판이 끝나면 결과 화면에 버튼 두 개가 뜬다 — PvP 면 **다시 매칭 / 나가기**,
AI 연습이면 **다시 하기 / 로비로**.

### Studio 에서 확인할 것

서버 출력창에 이 셋이 찍히면 정상이다.

```
[TCG] 카드 32 장 등록 완료
[TCG] 매칭 백엔드: 같은 서버 (Studio 테스트용)
[TCG] 로비 서버 준비 완료 — 빠른 대전 큐가 열렸습니다
```

| 확인 | 어떻게 |
|---|---|
| 시작 화면 | F5 → **빠른 대전 / AI 연습** 두 버튼 |
| AI 한 판 | **AI 연습** → 손패 클릭 · `E` 로 페이즈 진행 |
| 2인 매칭 | 테스트 탭에서 플레이어 **2명** → 두 창 모두 **빠른 대전** → 2초 안에 붙는다 |
| 좌석 | 두 창에서 각자의 이름이 **아래칸**에 있어야 한다 |
| 몰수 | 한 창을 닫으면 남은 창에 **승리** 가 뜬다 |

Studio 에서는 텔레포트가 안 되므로 매칭이 같은 서버 안에서 일어난다
(출력창의 "매칭 백엔드" 줄이 그 사실을 알려준다). 크로스서버 경로는 게시한 뒤에만 돈다 —
그 대신 `tests/smoke.luau` 가 흉내낸 환경에서 검증한다.

## 2. 터미널에서 한 판 하기

```powershell
lune run play          # 사람(P1) vs AI(P2)
```

Studio 를 켜지 않고 룰만 빠르게 확인할 때 쓴다.
**게임 안에서 도는 것과 완전히 같은 룰 엔진 코드**를 호출하므로,
여기서 이상하면 게임 안에서도 이상하다.

```
숫자      문맥에 맞는 기본 행동 (패 내기 / 공격 선언 / 방어 배정)
h <번호>  손패에서 카드 내기 (어느 페이즈든)
e         페이즈 종료
p         스택 대응 패스
l         최근 로그      ?  도움말      q  종료
```

번호가 가리키는 대상은 페이즈에 따라 바뀐다 — 메인이면 손패, 공격준비면 내 생물,
수비준비면 방어할 생물. 화면 위에 항상 표시된다.

## 3. 빠른 매칭

로비를 두지 않았다. 방 목록도, 대기실도, 돌아다닐 공간도 없다 — 접속하면 시작 화면이고
누를 것은 **빠른 대전**과 **AI 연습** 둘뿐이다.

### 큐는 서버를 넘어간다

로블록스 서버 하나에 동시에 붙어 있는 인원은 많지 않다. 같은 서버 안에서만 짝을 지으면
"큐를 눌렀는데 아무 일도 안 일어남" 이 기본값이 된다. 그래서 큐는 처음부터 크로스서버다.

```
A서버(김) ─AddAsync─┐
                    ├─→ [MemoryStore 큐] ←─ 아무 서버나 2초마다 ReadAsync 로 훑는다
B서버(이) ─AddAsync─┘                          │
                                               ├ 짝이 나오면 ReserveServerAsync 로 빈 서버 확보
                                               └ PublishAsync 로 전 서버에 알린다
                                                    │
                                    A서버 ─────────┴──────── B서버
                                 (김을 태움)              (이를 태움)
                                            │                │
                                            └─→ 예약 서버 ←──┘   = 대전 서버
```

MessagingService 가 필요한 이유는 하나다 — **텔레포트는 자기 서버의 플레이어에게만
걸 수 있다.** 짝을 지은 서버가 상대편을 직접 옮길 수 없으니, 상대가 붙어 있는 서버에게
"이 사람 태워보내라" 를 전해야 한다.

### 플레이스는 하나다

대전 서버는 **같은 플레이스를 `ReserveServerAsync` 로 잡은 것**이다. 플레이스를 둘로 나누면
카드 DB·룰 엔진·UI 를 두 곳에 배포해야 하고 둘의 버전이 어긋나는 순간을 막을 방법이 없다.
서버는 자기가 어느 쪽인지 부팅할 때 한 번 판단한다.

```lua
game.PrivateServerId ~= "" and game.PrivateServerOwnerId == 0   -- 예약 서버 = 대전
```

| | 공개 서버 (`Lobby`) | 예약 서버 (`Arena`) |
|---|---|---|
| 인원 | 여럿 | 매칭된 둘 |
| 하는 일 | 시작 화면 · 큐 · AI 연습 | PvP 한 판 |
| 끝나면 | — | 결과를 보여주고 로비로 되돌려보낸다 |

PvP 를 로비 서버에서 굴리지 않는 이유: 로비가 대전까지 맡으면 사람이 많이 붙은 서버일수록
느려져서 **매칭 운이 곧 플레이 품질**이 된다.

### Studio 에서 어떻게 확인하나

`TeleportService` 는 Studio 에서 아예 동작하지 않는다. 그래서 큐 백엔드를 둘로 나눠뒀다.

| 백엔드 | 언제 | 엔트리가 담기는 곳 |
|---|---|---|
| `Matchmaker/CrossServer.luau` | 실제 게임 | MemoryStore 큐 |
| `Matchmaker/Local.luau` | Studio | 서버 안 테이블 |

**짝짓기 규칙은 둘이 공유한다** (`src/shared/Matchmaking`). 누구와 누구가 붙는지,
어느 엔트리를 버리는지, 누가 몇 번 좌석인지는 같은 함수가 정한다 — 다른 것은
엔트리가 어디에 담기느냐뿐이다. 그래서 Studio 2인 테스트로 확인한 매칭 동작이
게시된 서버에서도 그대로다.

크로스서버 경로 자체(텔레포트·MessagingService·MemoryStore)는 **게시된 플레이스에서만
검증된다.** Studio 에서는 한 줄도 실행되지 않는다.

게시할 때 켜야 하는 것:

- 게임 설정 → 보안 → **Studio 의 API 서비스 접근 허용** (MemoryStore 를 Studio 에서 볼 때)
- 게임 설정 → 보안 → **서드파티 텔레포트 허용은 필요 없다** (같은 플레이스로만 이동한다)

### 짝짓기가 지키는 것

`src/shared/Matchmaking` 은 Roblox API 를 전혀 쓰지 않는 순수 함수라 테스트로 못 박아뒀다
(`tests/specs/matchmaking.luau`). 여기서 막는 사고는 셋이다.

| 사고 | 왜 생기나 | 어떻게 막나 |
|---|---|---|
| 자기 자신과 매칭 | 취소 → 재등록이 크로스서버에서 즉시 반영되지 않아 같은 userId 엔트리가 둘 남는다 | 같은 userId 는 가장 이른 것만 채택 |
| 취소한 사람이 상대를 끌고 감 | 큐에서 엔트리를 지울 수 없다 | 취소된 등록의 token 을 전 서버에 뿌려 거른다 |
| 유령 엔트리 | 서버가 죽으면 그 서버가 넣은 엔트리를 지울 사람이 없다 | TTL 90초 |
| 좌석 편향 | 먼저 온 사람이 항상 1번이면 좌석 이점이 큐 순서를 그대로 탄다 | 좌석과 선공을 매치 시드로 뽑는다 |

시드는 반드시 서버가 만든다. 시각이나 userId 로 유도하면 클라이언트가 셔플 순서를
예측할 수 있고, 카드 게임에서 그건 곧 치트다.

### 큐를 취소하면

MemoryStoreQueue 는 개별 항목 삭제를 지원하지 않는다(읽은 배치 단위로만 지운다).
그래서 취소해도 엔트리가 큐에 남는다. 거름망이 두 겹이다.

1. 취소된 **등록의 token** 을 MessagingService 로 전 서버에 뿌린다 → 짝짓기 단계에서 걸러진다
2. 그래도 짝이 지어졌다면 태우기 직전의 검사에서 막는다 (그 사람이 아직 큐에 있는가)

2번만 있으면 취소한 사람 본인은 안 끌려가지만 **짝이 된 상대가** 아무도 오지 않는
대전 서버로 끌려가 30초를 기다렸다 돌아온다. 그래서 1번이 필요하다.

차단이 사람(userId)이 아니라 **등록(token)** 단위인 것이 중요하다. 사람으로 막으면
"취소하고 마음 바뀌어 다시 누르기" 가 TTL(90초) 동안 통째로 막힌다.
등록마다 이름표를 달아두면 새 등록은 걸리지 않는다.

남은 유령 엔트리는 TTL 로 사라지고, 짝이 깨진 상대는 큐에 되돌아간다.

### 오래 기다리는 사람

TTL 은 **"주인 서버가 살아 있는가"** 를 재는 값이지 "얼마나 기다렸는가" 가 아니다.
둘을 안 나누면 90초 넘게 기다린 사람의 엔트리가 만료돼 큐에서 사라지는데,
화면에는 여전히 "상대를 찾는 중" 이 떠 있다. 영영 매칭되지 않고 본인은 이유를 모른다.

그래서 엔트리에 시각이 둘이다.

| | 무엇 | 쓰는 곳 |
|---|---|---|
| `joinedAt` | 줄 선 시각 | 매칭 순서 (갱신해도 뒤로 밀리지 않는다) |
| `refreshedAt` | 마지막으로 살아 있다고 알린 시각 | 만료 판정 |

주인 서버가 30초마다 `refreshedAt` 을 올려 다시 넣는다. 서버가 죽으면 아무도 안 올려주므로
그 엔트리는 TTL 을 지나 사라진다 — 청소부는 그대로 남는다.

한 가지 더. 짝을 못 지어도 **읽은 엔트리는 반드시 큐에 되돌려 놓는다.** `ReadAsync` 한
항목은 잠시 모든 서버에게 안 보이는데, 그대로 두면 두 사람의 "안 보이는 창" 이 어긋난 채
계속 어긋나서 영영 같은 읽기에 안 잡히는 수가 있다.

### 시드는 대전 서버가 뽑는다

텔레포트 데이터에는 **어느 판인지(matchId)와 자리(seat)만** 싣는다. 시드는 넣지 않는다.

클라이언트가 `GetLocalPlayerTeleportData()` 로 그 데이터를 읽을 수 있는데, 룰 엔진과
`Decks.starter()` 가 `ReplicatedStorage` 에 복제돼 있어서 **시드 하나만 있으면
`Rules.newMatch` 를 그대로 재현해 양쪽 덱 순서와 상대 손패를 전부 계산할 수 있다.**
카드 게임에서 그건 곧 게임 종료다.

두 사람이 실제로 만나는 곳은 대전 서버 하나뿐이라 서버끼리 시드를 합의할 이유가 없다.
`Arena` 가 `Random.new()` 로 직접 뽑는다 — 시각처럼 클라이언트가 짐작할 수 있는 값에서
유도하지 않는다.

### 상대가 안 오면

먼저 도착한 쪽은 30초만 기다리고 로비로 돌아가 **자동으로 다시 큐에 선다.** 부전승을
주지 않는 이유: 로블록스 텔레포트는 간헐적으로 실패하고, 안 온 것을 패배로 처리하면
네트워크 사고가 그대로 전적이 된다.

이게 있어야 `require(script.Parent.UI.Battle)` 같은 경로를 에디터가 따라간다.

`tests/` 는 Roblox 가 아니라 Lune 위에서 돈다. `lune setup` 이 만든 타입 정의를

지적하지 않게 된다). 유효한 이름 목록은 luau-lsp 확장의 `schemas/luaurc.json` 에 있다.

명령줄에서 에디터와 같은 검사를 돌려볼 수도 있다. luau-lsp 확장이 들고 있는 실행
파일을 쓴다 — CI 에는 안 넣었다. 확장 경로가 사람마다 다르고 버전마다 바뀌기 때문이다.

```powershell
$srv = "$env:USERPROFILE\.vscode\extensions\johnnymorganz.luau-lsp-*in\server.exe"
& (Resolve-Path $srv)[0] analyze --sourcemap sourcemap.json --base-luaurc .luaurc (Get-ChildItem src -Recurse -Filter *.luau)
```

`Ctrl+Shift+B` / 작업 실행에 미리 넣어둔 것들 (`.vscode/tasks.json`):


명령줄로도 같다:


## 5. CI

검사 내용은 하나다 — `scripts/ci.sh`. 로컬 훅과 GitHub Actions 가 **같은 것**을 돌린다.

| 단계 | 하는 일 |
|---|---|
| 문법 검사 | `tests/check.luau` — 전체 `.luau` 컴파일 |
| 룰 테스트 | `tests/run.luau` — 룰 · AI 자기대국 · 네트워크 계약 · 매칭 · 덱 · 클라이언트 판정 (161개) |
| 스모크 테스트 | `tests/smoke.luau` — 서버와 클라이언트를 **실제로 실행** (50개) |
| 플레이스 빌드 | `rojo build` 가 실제로 성공하는지 |

넷 다 합쳐 2초쯤이다.

### 카드 수치 바꾸기

**`src/shared/Cards/Sheet.luau` 한 파일에서 바꾼다.** 한 줄이 카드 한 장이고,
이름·코스트·공격력·생명력·태그·설명이 그 줄에 다 있다.

```luau
--   id             이름          코스트 공격력 생명력  태그       설명
{ "CRE_GUARD",   "성문 경비병",   2,     2,     3,   "",        "" },
{ "CRE_HAWK",    "창공의 매",     2,     2,     1,   "비행",     "" },
{ "CRE_SCRIBE",  "종군 서기",     2,     1,     2,   "",        "소환하면 카드 1 장을 뽑는다." },
```

태그는 한글로 쓴다(`신속`·`비행`·`도발`·`원거리`·`즉시시전`, 쉼표로 여러 개).

**설명 칸에 태그 설명을 다시 쓰지 않는다.** "비행 — 지상 생물은…" 은 태그 자체의 규칙이라
`Enums.KeywordText` 한 곳에 있고, 카드를 오른쪽 클릭하면 거기서 읽어온다. 여기 또 쓰면
상세 화면에 같은 문장이 두 번 뜬다 — 실제로 그랬고, `lune run tests/run.luau` 가
이제 태그 이름으로 시작하는 설명을 걸러낸다. 이 칸에는 그 카드만의 이야기를 쓰고,
태그밖에 없는 카드는 비워둔다.
마법은 효과 칸에 `damage(3, "생물또는플레이어")`, `draw(2)`, `destroy("적생물")` 처럼 적는다 —
쓸 수 있는 것 전부가 그 파일 맨 위 주석에 있다.

바꾼 뒤:

```powershell
lune run tests/cards.luau           # 지금 값이 표로 나온다. 잘못된 값도 여기서 잡힌다
lune run tests/cards.luau -- GUARD  # 일부만 보기 (id 조각으로 거른다)
lune run tests/balance.luau         # 판이 어떻게 달라졌는지 AI 자기대국으로 잰다
```

오타를 내면 게임이 뜬 뒤가 아니라 도구에서 한 줄로 잡힌다:

```
카드 표(src/shared/Cards/Sheet.luau)에 문제가 있습니다
  CRE_GUARD: 모르는 태그 '비행행'
```

`Cards/Core.luau` 는 그 표를 엔진이 읽는 모양으로 펴는 변환기다 — 카드가 늘어도
그 파일은 그대로이므로, 수치를 만질 때 열 일이 없다.

### 밸런스 계측 (테스트가 아니다)

```powershell
lune run tests/balance.luau              # 60판
lune run tests/balance.luau -- --games 200
```

AI 둘이 스타터 덱으로 여러 판 두게 하고 판 길이 · 덱 사용량 · 손패 · 멀리건 비율을 뽑는다.
**통과/실패가 없다** — 숫자를 보고 사람이 판단한다. 그래서 CI 에 넣지 않았다.
덱이나 카드를 건드릴 때 전후를 같은 자로 재려고 만들었다.

### 클라이언트 코드는 어떻게 테스트하나

`src/client` 는 `game:GetService` 를 쓰므로 Lune 에서 그냥은 안 돌아간다. 두 갈래로 본다.

| 무엇 | 어디서 | 어떻게 |
|---|---|---|
| 클릭 → 판정 (`Controller`) | `tests/specs/controller.luau` | `RobloxEnv.newLoader()` 가 `src/shared` 와 `src/client` 를 **한 캐시로** 마운트하고, `game:GetService("ReplicatedStorage"):WaitForChild("Shared")` 만 흉내낸다. 서버가 보낼 스냅샷(`viewFor` → `packView`)을 그대로 태워 하이라이트를 확인한다 |
| 화면 (`Battle`·`Home`) | `tests/smoke.luau` | 진짜 인스턴스 트리 위에서 버튼을 눌러보고 텍스트를 읽는다 |

캐시를 나누면 안 된다 — `src/client` 가 룰을 다시 로드하면 `Cards.load()` 가 한쪽 사본에만
남아 클라이언트 쪽 `Registry.mustGet` 이 "등록되지 않은 카드" 로 죽는다.
Roblox 에서는 `ReplicatedStorage` 의 같은 ModuleScript 를 공유하므로, 한 벌만 있어야 실제와 같다.

### 왜 `.ps1` 과 `.sh` 가 둘 다 있나

검사 목록은 `scripts/ci.sh` **하나뿐**이다. 사람도, 커밋 훅도, GitHub Actions 도 그걸
돌린다 — 목록이 두 곳에 있으면 반드시 어긋난다.

`.ps1` 은 그걸 부르기만 하는 껍데기다. 윈도우 PowerShell 에는 `sh` 가 없어서
(Git 이 `sh.exe` 를 깔아두지만 PATH 에 올려주지 않는다) `sh scripts/ci.sh` 가
"명령을 찾을 수 없음" 으로 끝나기 때문이다. `.ps1` 이 `sh.exe` 를 찾아서 넘긴다.

`studio.ps1` 은 한 가지를 더 한다 — `.rbxlx` 파일 연결이 없는 환경에서는
`start build.rbxlx` 도 실패하므로, Studio 실행 파일을 직접 찾아 넘긴다.
(Git Bash 에서 작업한다면 `.sh` 쪽을 그대로 써도 된다)

### 로컬 (원격 없이도 된다)

```powershell
git config core.hooksPath .githooks   # 이 저장소에서 한 번만
```

이후 **커밋할 때마다** `.githooks/pre-commit` 이 로컬 CI 를 돌린다.
통과하면 아무 말 없이 커밋되고, 실패하면 커밋이 막히면서 실패한 검사만 출력된다.

```powershell
scripts\ci.cmd            # 직접 돌려보기 (결과 전부 출력)
git commit --no-verify    # 한 번만 건너뛰기
git config --unset core.hooksPath   # 훅 끄기
```

훅을 `.git/hooks/` 가 아니라 `.githooks/` 에 두고 `core.hooksPath` 로 가리키는 이유:
`.git/` 안은 버전 관리가 안 된다. 이렇게 두면 훅 자체가 커밋되어 남는다.

한계 하나 — 검사 대상은 **작업 트리**다. 일부 파일만 stage 한 커밋이면 실제 커밋 내용과
다를 수 있어서, 그럴 때는 훅이 먼저 경고한다. (정확히 하려면 stash 를 써야 하는데
훅이 실패할 때 작업물을 잃을 위험이 생겨서 경고 쪽을 택했다)

### GitHub (푸시하면 자동)

`.github/workflows/ci.yml` 이 같은 순서를 돌린다. 다른 점은 둘:

- **툴체인**을 `aftman.toml` 그대로 설치한다 → 로컬과 CI 가 같은 rojo/lune 을 쓴다
- 나온 `build.rbxlx` 를 **아티팩트로 올린다** → 받아서 더블클릭하면 그 커밋의 게임이 열린다

서식 검사(StyLua)는 별도 잡이고 `continue-on-error: true` 다. 아래 이유로 앞으로도 그렇다.

### 왜 자동 정렬을 껐나

`stylua` 는 줄 길이를 **바이트로 센다.** 한글은 글자당 3바이트라, 화면에서 60자쯤 되는
줄을 180바이트로 보고 쪼갠다:

```luau
-- 손으로 맞춘 것
return false, "지상 생물은 '비행' 생물을 공격할 수 없습니다 ('비행' 또는 '원거리' 필요)"

-- stylua(폭 110)가 바꾸려는 것
return false,
	"지상 생물은 '비행' 생물을 공격할 수 없습니다 ('비행' 또는 '원거리' 필요)"
```

폭을 넓히면 이번엔 반대로, 여러 줄로 나눠 쓴 조건문을 한 줄로 합친다. 실제로 재보면
어느 값도 0 이 되지 않는다:

| `column_width` | 어긋나는 파일 |
|---|---|
| 110 | 32개 |
| **140 (현재)** | **19개** |
| 200 | 24개 |

이 저장소는 한글 **표시 폭** 기준으로 손으로 맞춰 왔고 stylua 는 그 기준을 모르므로,
`.vscode/settings.json` 에서 luau 의 `editor.formatOnSave` 를 껐다. 포매터 지정은
남겨뒀으니 필요하면 `Shift+Alt+F` 로 그 파일만 정렬할 수 있고,
`stylua src tests play.luau` 로 전체를 한 번에 정렬할 수도 있다 — 다만 그러면
한글 문자열이 여기저기 쪼개진다.

### 검사 셋이 각자 메우는 구멍

| | 무엇을 아는가 | 무엇을 모르는가 |
|---|---|---|
| `check.luau` | 전부 컴파일된다 | 돌려보면 죽는지 |
| `run.luau` | 룰이 맞다 (`src/shared` 를 실제로 실행) | 서버·클라이언트가 도는지 |
| `smoke.luau` | 서버·클라이언트가 실제로 돈다 | 화면이 예쁜지 |

`run.luau` 가 `src/shared` 만 로드하는 이유는 서버/클라이언트 코드가 Roblox API 를 쓰기
때문이다. 그래서 오랫동안 `src/server` · `src/client` 는 **아무도 실행해본 적 없는 상태로**
커밋됐다 — 문법이 맞아도 `nil` 인덱싱, 잘못된 require 경로, 없는 Enum 항목, 오타난 속성은
Studio 를 켜서 그 화면이 뜰 때까지 아무도 모른다. `smoke.luau` 가 그 구멍을 메운다.

## 스모크 테스트 — Studio 를 켜기 전에

```powershell
lune run tests/smoke.luau
```

`tests/lib/Roblox*` 가 Roblox 표면(Instance · 서비스 · 데이터타입 · task)을 흉내내고,
그 위에서 **`src/server` 와 `src/client` 를 진짜로 실행한다.** 서버를 부팅하고, 사람을
접속시키고, **화면의 버튼을 눌러서** 매칭과 대전을 시킨다. 판정도 화면을 읽어서 한다 —
내부 변수를 들여다보지 않으므로, 통과했다는 말은 "사람이 그 버튼을 눌렀을 때 그 화면이
나온다" 는 뜻이다.

```lua
Screen.click(Screen.findButton(kim.PlayerGui, "빠른 대전"))
world:advance(6)                       -- 6초가 흘렀다 (가상 시계)
t:eq(panelName(kim, "MyPanel"), "Kim") -- Kim 화면의 아래칸은 Kim 이어야 한다
```

확인하는 시나리오:

| | 내용 |
|---|---|
| 로비 | 시작 화면 · 큐 등록 · 취소 · 혼자면 매칭 안 됨 |
| AI 연습 | 판 시작 · **여러 턴 진행** · 항복 · 로비 복귀 |
| 같은 서버 매칭 | 두 사람 매칭 · **각자 자기가 아래칸** · 선공이 한 명 · 이탈 몰수 |
| 크로스서버 매칭 | 서로 다른 서버 → 예약 서버에서 만남 · 좌석/시드 일치 · 취소 반영 |
| 화면 배율 | 720 · 900 · 1440 창에서 UI 배율이 맞게 잡히는지 |

**크로스서버 시나리오가 특히 중요하다.** 그 경로는 Studio 에서 한 줄도 실행되지 않아서,
이 테스트가 없으면 게시하기 전까지 검증할 방법이 아예 없다.

### 엄격하게 흉내낸다

느슨한 흉내는 "테스트는 초록불인데 Studio 는 빨간 줄" 을 만든다. 그래서 모르는 것은
조용히 넘기지 않고 그 자리에서 실패시킨다.

```
Instance.new("TextLable")        → 없는 클래스입니다
label.TextColour3 = ...          → TextLabel 에는 그 속성이 없습니다
Enum.TextXAlignment.Centre       → 없는 항목입니다
game:GetService("DataStore")     → 모르는 서비스입니다
```

속성 표는 `tests/lib/Roblox/Instance.luau` 에 손으로 적혀 있다. 새 속성을 쓰기 시작하면
거기에도 한 줄 추가해야 하는데, 그 한 줄이 "Studio 를 켜서 그 화면이 뜰 때까지 아무도
모르는 오타" 를 없앤다.

### 흉내내지 않는 것

- 픽셀 레이아웃 — `UIListLayout` 이 실제로 정렬하지 않는다. **화면이 예쁜지는 모른다**
- 복제 지연 — `FireClient` 가 즉시 도착한다
- 실제 MemoryStore / MessagingService / 텔레포트 — 동작을 흉내낼 뿐 실제 응답이 아니다
- 실제 시간 — 시계는 `world:advance` 로만 흐른다

그래서 스모크 테스트가 통과해도 **Studio 를 한 번은 켜봐야 한다.** 다만 켰을 때
출력창이 빨갛지 않다는 것은 미리 안다.

### 서버 / 클라이언트 역할

상태의 주인은 서버 하나다. 클라이언트는 행동을 **요청**만 하고,
통과 여부는 서버의 `Rules` 액션 함수가 정한다.

그런데 클라이언트도 같은 `Rules` 모듈을 갖고 있다. 버튼을 켜고 끄고
초록 테두리를 칠할 때 `Rules.canPlayCard` · `Combat.legalAttackTargets` ·
`Combat.canBlock` · `Effects.validateTarget` 을 **서버가 부르는 것과 같은 코드**로 부른다.
그래서 "화면엔 켜져 있었는데 서버가 거부" 가 구조적으로 생기지 않는다.
서버가 그래도 다시 검증하는 건 클라이언트를 못 믿어서가 아니라, 같은 코드라 공짜라서다.

### 화면이 무엇을 말하는가

카드 게임에서 가장 자주 하는 실수는 "지금 내 차례가 아닌데 카드를 누르는 것" 이다.
그래서 **지금 누가 두는가** 를 세 군데에서 동시에 말한다.

| 어디 | 무엇 |
|---|---|
| 보드 테두리 | 내 차례면 초록, 상대 차례면 붉게. 카드를 보고 있어도 주변시로 들어온다 |
| 행동 바 배너 | `내 차례` / `상대 차례` — 턴 주인이 아니라 **행동권자** 다 |
| 상단 좌측 | `턴 3 · 상대 턴` — 턴 주인은 따로 표시한다 |

턴 주인과 행동권자를 나눠 적는 이유: 수비준비 페이즈에서는 **상대 턴인데 내가 둔다.**
하나로 합치면 그 순간 화면이 "상대 턴" 이라고 말하면서 내 입력을 기다리게 된다.

놓치면 그대로 오조작이 되는 카드 상태도 색 있는 칩으로 띄운다.

| 표시 | 뜻 |
|---|---|
| 기울어진 카드 + `탭됨` | 공격도 방어도 못 한다 (예전엔 4도 회전이라 사실상 안 보였다) |
| `공격 불가` | 이번 턴에 소환돼서 공격만 못 한다. **방어는 된다** |
| `공격` / `방어` 배지 | 전투 배정 결과 |
| 굵은 초록 테두리 | 지금 누를 수 있는 대상 |

### 글자 크기와 화면 배율

글자 크기는 위젯마다 정하지 않고 `Theme.text` 척도에서 고른다. 그러지 않으면
"여기만 10, 저기만 11" 이 쌓여서 전체를 키울 방법이 없어진다. 가장 작은 값이 12 인데,
로블록스는 창 크기가 제각각이고 텔레비전으로도 보기 때문이다.

레이아웃 치수(`Theme.size`)는 **일부러 안 키웠다.** 배치가 고정 픽셀이라 카드를 10px
키우면 보드 절반마다 20px 씩 먹어서 768px 창에서 가운데 영역이 음수가 된다.
대신 `Widgets.autoScale` 이 창 높이에 맞춰 화면 전체를 늘렸다 줄인다.

```lua
scale.Scale = clamp(뷰포트높이 / 900, 0.8, 1.5)
root.Size   = UDim2.fromScale(1 / scale, 1 / scale)   -- UIScale 이 곱한 걸 되돌린다
```

두 번째 줄이 핵심이다. UIScale 은 자식의 **scale 성분까지** 곱하므로 그것만 걸면
가로 전체를 차지하는 위젯이 화면 밖으로 나간다. root 를 1/배율로 잡아 상쇄하면
root 안쪽은 창 크기와 무관하게 **항상 세로 900 짜리 화면**이 된다 —
고정 레이아웃의 세로 예산이 창 크기에 따라 무너지던 문제가 사라지고,
큰 모니터에서는 같은 배치가 그냥 크게 보인다.

`tests/smoke.luau` 의 "화면 배율" 이 720 · 900 · 1440 세 창에서 이걸 확인한다.

### 좌석 — "나는 1번" 이 아니다

PvP 에서 나는 1번 좌석일 수도 2번일 수도 있다. 그래서 클라이언트에는 "내 좌석" 상수가
없고, 서버가 스냅샷에 실어 보내는 `viewerId` 가 그 자리를 대신한다.

```lua
self.me  = state.viewerId          -- Controller / Battle 이 매 렌더마다 채운다
self.foe = GameState.opponentOf(self.me)
```

화면도 좌석 번호로 만들지 않는다. 패널은 "아래칸/위칸" 으로 만들어두고, 누를 때
그 시점의 `self.me` / `self.foe` 를 가리킨다. 이게 어긋나면 2번 자리에 앉은 사람은
상대 패를 자기 손패로 보고 자기 생물을 상대 필드에서 찾게 된다 —
`tests/specs/net.luau` 의 "2번 좌석 시점" 이 그 대칭을 못 박아둔다.

서버 쪽도 같다. **어느 좌석의 행동인지는 클라이언트가 말하지 않는다.** `MatchRunner` 가
보낸 `Player` 로 좌석을 찾는다. 그래서 상대 좌석의 카드를 내는 요청은 만들 수조차 없다.

### 왜 Net 이 필요한가

Roblox 의 RemoteEvent 직렬화는 "1 부터 이어지는 배열" 과 "문자열 키 딕셔너리" 만
안전하게 옮긴다. 그런데 룰 상태에는 카드 인스턴스 id(숫자, 비연속)를 키로 쓰는
테이블이 여럿이다 — `state.cards[instanceId]`, `combat.blocks[blockerId]`,
구멍 뚫린 `targets[effectIndex]`. 그대로 실으면 **에러 없이 조용히** 모양이 바뀐다.

`src/shared/Net` 이 보내기 직전에 전부 배열로 펴고 받는 쪽에서 되돌린다.
Studio 를 켜야만 드러날 종류의 버그라서 `tests/specs/net.luau` 가
"스냅샷 안에 숫자 키 딕셔너리가 하나도 없다" 를 못 박아둔다.

### AI

`AI.act(state, playerId)` 는 **한 번에 한 수**만 두고 돌려준다. 호출자가 루프를 돌리므로
수와 수 사이에 연출/딜레이를 끼워넣을 수 있다. AI 는 상태를 직접 만지지 않고
사람과 똑같이 `Rules` 액션만 호출한다 — **AI 가 룰을 어기는 것이 구조적으로 불가능하다.**

테스트 스위트는 매번 AI 자기대국 5판을 끝까지 돌려 교착과 존 무결성을 확인한다.
단위 테스트로는 안 잡히는 "아무도 둘 수 없는 상태"가 여기서 걸린다.

`MatchRunner` 의 좌석은 **사람이거나 AI** 다. 좌석에 `player` 가 있으면 스냅샷을 쏘고
입력을 기다리고, `ai` 가 있으면 대신 한 수를 둔다. PvP 는 "AI 좌석이 하나도 없는 매치"
일 뿐이라 PvE 와 코드 경로가 갈라지지 않는다 — 갈라지면 둘 중 하나는 반드시 썩는다.

### 왜 Roblox 코드를 Studio 없이 테스트할 수 있는가

`tests/lib/RobloxEnv.luau` 가 `src/shared` 디렉터리를 읽어 Instance 비슷한 노드 트리를
만들고, `script` 와 `require` 를 주입한 환경에서 각 모듈을 실행한다.
**룰 엔진 코드에는 테스트를 위한 변환이나 분기가 한 줄도 없다** — Rojo 가 Studio 로
밀어넣는 파일과 테스트가 검증하는 파일이 바이트 단위로 같다.

### 턴 구조 (기획서 그대로)

```
Untap  → 턴 플레이어의 모든 카드 언탭, 코스트 소환 횟수 리셋   (자동)
Draw   → 1장 드로우 (선공 1턴은 생략)                          (자동)
Main   → 코스트 소환 · 생물 소환 · 마법 시전  / 상대는 즉시시전만
AttackPrep  → 공격자 선언
DefensePrep → 수비측: 방어 배정 · 소환(탭) · 마법

```

공격자가 하나도 없으면 `DefensePrep` / `Combat` 은 자동으로 건너뛴다.

### 태그 5종

| 태그 | 구현 |
|---|---|
| **신속** | 소환한 턴에 바로 공격 가능. 수비준비 페이즈에서 **언탭**으로 등장해 즉시 방어 가능 |
| **비행** | 지상(비행X) 비원거리 생물은 비행을 **공격도 방어도** 못 함 |
| **도발** | 필드에 있으면 상대는 플레이어를 직접 공격 불가. 비행도 못 무시함 |
| **원거리** | 비행을 공격/방어 가능, 도발 무시. 대신 플레이어 직공 데미지 **절반(내림)** |
| **즉시시전** | 상대 메인 / 본인 메인 / 본인 수비준비에 발동. 스택 위 소환·마법을 무효화하거나 덱으로 되돌림 |

### 코스트

- 덱 60장 중 원하는 만큼 코스트 카드. 턴당 1장 필드에 소환.
- 코스트 카드는 **언탭 상태로 등장**해 그 턴 바로 탭해서 쓸 수 있고, 다음 자기 언탭 스텝까지 언탭되지 않는다.
- 생물/마법을 낼 때 언탭된 코스트 카드가 순서대로 탭되며 지불된다.

### 멀리건 (판 시작 전)

손패가 마음에 안 들면 **한 번, 벌칙 없이** 통째로 바꾼다. 손패를 덱에 되돌려 섞고
같은 장수를 다시 뽑는다. 물리면 그 자리에서 그 사람의 결정은 끝난다 —
새 손패를 보고 또 고를 수 있다면 그건 무료 1회가 아니다.

동시에 묻지 않고 **선공부터 차례로** 묻는다. 각자 자기 손패만 보므로 결과는
동시에 하는 것과 같고, 대신 "지금 누가 결정할 차례인가" 가 `activePlayerId` 하나로
표현된다 — 우선권·화면·AI 가 전부 이미 그것만 보고 있어서 관문을 위해 따로
고쳐야 하는 곳이 없다.

### 덱 순환 — 왜 드로우를 넣었나

2026-09-09 계측(`lune run tests/balance.luau`, AI 자기대국 120판, 같은 시드 집합):

| | 개편 전 | 개편 후 |
|---|---|---|
| 스타터 덱의 드로우 카드 | 0장 | 12장 (통찰 4 · 종군 서기 4 · 서고 개방 1 등) |
| 한 판에서 쓴 덱 | 21.5장 / 60장 | **25.4장 / 60장** (+18%) |
| 턴 시작 손패(판 전체 평균) | 3.42장 | **3.90장** |
| 판 길이 | 29.9턴 | 29.4턴 |

**드로우는 "카드를 얼마나 보는가" 를 고쳤지만 판 길이는 거의 안 줄였다.**
판이 긴 원인은 드로우가 아니라 라이프 30 대비 보드 교착 쪽이고, 그건 밸런스 문제라
따로 다룬다. 60장 덱에 턴당 1드로우면 25턴짜리 판에서 덱의 40% 정도를 보는 게
구조적 상한이다 — 그 이상은 덱을 줄이거나(기획서 60장 유지 결정) 턴당 드로우를
늘려야 움직인다.

`SPL_INSIGHT`(통찰)를 **일부러 즉시시전이 아닌 일반 마법**으로 만든 이유도 여기 있다.
즉시시전으로 두면 AI 든 사람이든 대응용으로 손에 쥐고 있어서 덱이 도는 데 기여하지
않는다 — 실제로 그렇게 만들었다가 계측에서 그대로 드러났다.

### 스택 (즉시시전이 동작하는 방식)

카드를 내면 즉시 효과가 나지 않고 스택에 올라간다 → 상대에게 대응 창이 열린다 →
아무도 대응하지 않으면 해결된다. 그래서 "상대가 소환하려는 생물을 덱으로 되돌리기",
"상대 마법 무효화"가 성립한다. **무효화당해도 지불한 코스트는 환불되지 않는다.**

## 덱 편집과 저장

시작 화면의 **덱 편집** 에서 자기 덱을 짜고 저장한다. 저장된 덱으로 다음 판이 열린다.

| | |
|---|---|
| 저장 위치 | `DataStore` — 이름 `PlayerDecks_v1`, 키는 `user_<UserId>` |
| 저장 모양 | 엔트리 배열 `{ { id = "COST_BASIC", count = 24 }, ... }` |
| 검증 | `Decks.validateEntries` **한 곳**. 화면·저장·매치 시작이 같은 함수를 부른다 |

### 실패해도 게임은 돈다

DataStore 는 없을 수도 실패할 수도 있다 — Studio 에서 "API 서비스 접근 허용" 이 꺼져
있으면 호출 자체가 에러고, 게시된 서버에서도 한도에 걸리거나 잠깐 실패한다.
그래서 `DeckStore` 는 실패를 정상 경로로 다룬다.

- 못 읽으면 **스타터 덱**으로 논다 (nil 을 돌려주지 않는다 — 부르는 쪽마다 "없으면 스타터"
  를 다시 쓰게 되고, 한 곳이 빠지면 덱 없이 대전이 열린다)
- 못 쓰면 "저장하지 못했습니다" 를 화면에 알리되, **그 덱은 이 서버에 있는 동안 유효하다**
  (캐시에는 들어간다). 저장 실패로 대전을 막지 않는다
- 저장된 값도 믿지 않는다. 읽을 때 다시 검증하고, 규칙에 안 맞으면 스타터로 되돌린다

### 대전 서버는 덱을 어디서 받나

실제 PvP 는 로비가 아니라 **예약 서버**에서 열린다. 덱을 짠 곳과 판이 열리는 곳이
다른 서버라, 덱이 그 사이를 건너가야 한다.

**텔레포트 데이터로 나르지 않는다.** 그 값은 클라이언트가
`GetLocalPlayerTeleportData()` 로 읽을 수 있고, 읽을 수 있으면 고칠 수 있다고 봐야 한다
— 실어 보내는 순간 "아무 카드나 60장" 으로 판을 여는 길이 열린다.

대신 **도착한 사람의 UserId 로 대전 서버가 DataStore 에서 직접 읽는다**(`Arena:loadDeck`).
사람마다 덱은 하나뿐이라 "어느 덱인지" 를 가리킬 것도 없다. 읽기는 도착할 때마다 한 번,
상대를 기다리는 동안 한다 — 두 사람 덱이 다 들어온 뒤에 판이 열린다.

읽기가 실패해도 판은 열린다. `DeckStore:get` 이 스타터 덱을 돌려주기 때문이다
(위 "실패해도 게임은 돈다").

| 경로 | 덱이 어디서 오나 |
|---|---|
| AI 연습 · Studio 같은 서버 매칭 | 로비 서버의 `DeckStore` (`Lobby:deckFor`) |
| 게시된 PvP (예약 서버) | 대전 서버가 UserId 로 다시 읽는다 (`Arena:loadDeck`) |
| 덱이 없거나 못 읽음 | 스타터 덱 |

확인은 `lune run tests/smoke.luau` 의 "저장한 덱으로 대전" 절이 한다. 판정은
**손패를 읽어서** 한다 — 클라이언트에게 덱 내용은 안 내려가므로(`viewFor` 가 지운다)
"손에 들어온 카드가 전부 내 덱에 있는 카드인가" 를 본다. 두 사람에게 서로 겹치지 않는
덱을 쥐여주므로 좌석이 뒤바뀌는 경우도 같이 걸린다.

### 왜 엔트리 모양으로 저장하나

60칸 배열 대신 `{ id, count }` 목록으로 저장한다. 전송량 때문이기도 하지만,
무엇보다 **사람이 읽을 수 있어야** 저장된 값을 보고 문제를 짚을 수 있다.
Roblox 직렬화가 안전하게 다루는 모양이기도 하다.

### 카드 자세히 보기

카드를 **오른쪽 클릭**하면 오른쪽에 상세가 뜬다 — 이름·종류·코스트·공격력·생명력·태그·설명,
그리고 내 덱에 몇 장 들어 있는지. 목록의 한 줄은 이름과 숫자까지밖에 못 담는데,
덱을 짜려면 그 카드가 무엇을 하는지를 봐야 한다.

왼쪽 클릭은 넣고 빼는 것, 오른쪽 클릭은 들여다보는 것으로 나눴다. 한 버튼에 섞으면
"보려고 눌렀는데 덱이 바뀌는" 일이 생긴다. 상세를 열어둔 채 카드를 넣고 빼면
"내 덱에 N장" 도 같이 따라간다.

이 상자는 `CardView.detail` 로, **전투 화면도 같은 것을 쓴다.** 태그가 무슨 효과인지도
여기서 읽는다 — 위 "튜토리얼" 절 참조.

### 목록은 위에서부터 쌓아야 한다

`Widgets.listLayout` 의 세로 정렬 기본값은 **Center** 다. 스크롤 영역에서 이걸 쓰면
내용이 길어졌을 때 위아래로 똑같이 넘쳐서 **맨 위가 잘리고 스크롤로도 못 올라간다**
(캔버스는 0 부터인데 내용이 그 위로 밀려 있다). 실제로 카드 목록의 생물 첫 줄이
그렇게 안 보였다. 스크롤되는 목록에는 `VerticalAlignment.Top` 을 명시한다.

가로로 스크롤하는 줄(전투 화면의 손패·필드)도 같은 함정이다. 다만 여기서는 늘 왼쪽으로
붙이면 카드가 두세 장일 때 화면이 왼쪽으로 쏠린다. 그래서 `Battle.alignWhenOverflowing`
이 넓이를 보고 그때그때 바꾼다 — **넘치면 왼쪽, 아니면 가운데.**
(`AbsoluteContentSize` / `AbsoluteSize` 가 바뀔 때마다 다시 판단한다)

### 화면이 먼저 막고, 서버가 다시 막는다

60장이 아니면 저장 버튼이 아예 꺼진다. "저장을 눌렀더니 거부당하는" 것보다
"아직 못 누른다" 가 낫기 때문이다. 그래도 서버는 다시 검증한다 —
클라이언트를 믿어서가 아니라, 같은 함수라서 공짜다.

## 튜토리얼

시작 화면의 **튜토리얼** 은 규칙 설명서가 아니라 **가이드가 붙은 한 판** 이다.
진짜 룰로 진짜 판을 두면서, 단계마다 지금 무엇을 하면 되는지 말풍선으로 알려주고
시킨 것 말고는 못 누르게 잠근다.

| | |
|---|---|
| 판을 여는 조건 | `Lobby:startTutorial` — 고정 시드, 튜토리얼 전용 덱 두 벌, 상대 라이프 12, Easy AI, 사람이 선공 |
| 코치 | `src/client/Tutorial.luau` — 단계 · 말풍선 · 잠금 |
| 화면 | `Battle` 의 `Coach` 상자(보드 한가운데)와 손패 잠금(`lockedHand`) |
| 진입 | 버튼으로만. 처음 접속한 사람에게 강제로 띄우지 않는다 |

### 무엇을 가르치나

| 구간 | 가르치는 것 |
|---|---|
| 멀리건 | 손패를 한 번 무료로 바꿀 수 있다 |
| 코스트 | 카드를 내려면 코스트가 필요하다. 한 턴에 한 장 |
| 소환 | 지금 낼 수 있는 카드가 밝게 켜진다 |
| **탭 · 언탭** | 코스트를 뽑으면 카드가 눕는다(탭). 내 턴이 시작할 때 다시 선다(언탭) |
| 페이즈 | 메인 → 공격준비 → 수비준비 |
| 소환 멀미 | 방금 나온 생물은 이번 턴에 공격 못 한다 (신속은 예외) |
| 방어 | 상대가 공격하면 막을 생물을 고른다. 안 막으면 라이프로 들어온다 |
| 공격 | 생물을 고르고 대상을 고른다. 공격을 선언한 생물은 탭된다 |
| **태그 5종** | 자유 구간에서 말풍선이 도발 · 비행 · 원거리 · 신속 · 즉시시전을 차례로 설명한다 |

### 태그는 코치가 읊지 않는다 — 찾아보는 법을 가르친다

여기서 두 번 틀렸다.

1. 처음에는 **화면에 나와 있는 태그**만 골라 설명했다. 카드를 보면서 읽는 게 낫다고
   봤는데, 재보니 한 판에 두 종밖에 안 나왔다
2. 그래서 **다섯 종을 무조건 돌렸다.** 그랬더니 비행 생물이 한 마리도 없는 판에서
   비행 설명이 떴다 — 읽는 사람은 화면에서 그걸 찾다가 못 찾는다

어느 쪽도 맞지 않았다. 말풍선은 세 줄이라 다섯 종을 담을 수 없고, 판은 그중 몇 종만
보여준다. **말풍선으로 사전을 만들려던 게 잘못이었다.**

지금은 카드를 **오른쪽 클릭**하면 태그 효과까지 나오고(`CardView.detail`),
코치는 그 손짓 하나만 가르친다 — 예로 들 카드는 화면에 실제로 있는 것 중에서 고른다.
한 번 눌러보면 잔소리를 멈춘다(`Tutorial:markInspected`). 배운 것을 계속 시키면
말풍선이 배경이 된다.

끝나는 자리에서 한 번 더 짚는다(`Controller:endNote`) — **"카드를 오른쪽 클릭하면
태그가 무슨 효과인지 볼 수 있어요. 더 다양한 카드는 시작 화면의 [덱 편집] 에서!"**

### 카드 상세는 두 화면이 같은 것을 쓴다

`CardView.detail` 하나를 덱 편집과 전투가 함께 쓴다. 같은 카드를 어디서 열든 같은 설명이
나와야 한다. 덱 편집에만 붙는 것은 마지막 줄("내 덱에 3장")뿐이다 — 전투 중에는 덱을
못 고치므로 그 줄이 의미가 없다.

**태그 설명은 `Enums.KeywordText` 한 곳에서 읽는다.** 카드에 적힌 설명문(`Sheet.luau`)은
카드마다 따로 쓰여 있어서, 같은 태그가 카드마다 다르게 설명되거나(창공의 매 vs 매부리)
아예 빠진다(폭풍 비룡은 "비행, 신속" 이 전부다).

왼쪽 클릭과 오른쪽 클릭을 나눈 것은 덱 편집과 같은 이유다 — 한 버튼에 섞으면
"보려고 눌렀는데 카드가 나가는" 일이 생긴다. 같은 카드를 다시 오른쪽 클릭하면 닫힌다.

### 말풍선은 세 줄까지

코치 상자는 520 × 74 — 본문 크기로 **세 줄** 예산이다. 보드 가운데는 위아래 패널과
필드가 고정 높이라 상자를 더 키울 자리가 없다. 문구를 쓸 때 줄당 35자쯤을 넘기지 않는다.

### 왜 대본이 아니라 조건인가

"1턴에 코스트, 2턴에 소환" 같은 턴 번호 대본은 처음 한 번만 맞는다. 다시 하기를
누르면 덱이 새로 섞이고, `Sheet.luau` 에서 수치를 고치면 AI 가 다른 수를 두고,
사람이 예상 밖의 순서로 눌러도 어긋난다.

그래서 단계마다 **판 상태를 보는 함수** 두 개를 둔다.

    done(view, me)   이 단계는 끝났는가        → 다음 단계로
    skip(view, me)   이 판에서는 가르칠 수 없나 → 건너뛴다

예를 들어 "생물을 소환하세요" 단계는 *지금 낼 수 있는 생물이 손에 없으면* 스스로
건너뛴다. 1코 생물이 손에 안 잡힌 판에서 낼 수 없는 카드를 가리키며 소환하라고
하면 거기서 막히기 때문이다.

단계는 되돌아가지 않는다. 조건만으로 매번 다시 고르면 "필드에 생물이 있다" 같은
조건이 생물이 죽는 순간 거짓이 되면서 이미 배운 단계로 돌아간다.

### 잠금은 두 가지 원칙으로

**고르기 시작한 뒤에는 잠그지 않는다.** 대상 지정 · 공격 대상 · 방어 대상을 고르는
중에 누를 수 있는 것은 이미 룰이 초록으로 좁혀놨고, 거기서 코치가 또 막으면
고르다 만 채로 갇힌다. 코치가 통제하는 것은 "무엇을 시작할 수 있나" 뿐이다.

**뒤로 갈수록 푼다.** 멀리건 → 코스트 → 소환 → 페이즈 종료 → 상대 턴 → 두 번째 메인
까지가 잠긴 구간이고, 공격을 배우는 단계부터는 자유다. 기본을 배운 뒤에도 계속 손을
잡고 있으면 그건 튜토리얼이 아니라 시연이다.

판정은 `Controller:coachAllow()` 한 곳에서 나온다. 화면(꺼진 버튼 · 흐린 카드),
클릭 처리, **단축키(E · P)** 가 전부 같은 허용표를 본다 — 화면에서만 끄면
E 키로 코치를 앞질러 갈 수 있다.

### 어떻게 검증하나

`lune run tests/smoke.luau` 의 "튜토리얼" 절에 **학생** 이 하나 산다.
대본을 따라가지 않고, 화면에서 **켜진 것만** 골라 누른다 — 꺼진 버튼은 안 누르고,
흐린 손패 카드는 안 내고, 초록 테두리가 없는 생물은 안 고른다(`isLit`).

그 학생이 판을 이기면 통과다. 코치가 어느 단계에서든 아무것도 안 켜주면 학생은
거기서 맴돌고, 테스트는 "진도가 안 나갔습니다" 로 실패한다.

**무엇을 말했는지도 같이 본다.** 판 내내 말풍선을 모아 두고 탭·언탭 설명이 나왔는지,
카드를 들여다보는 법을 알려줬는지 확인한다. 여기서 낱말 하나로 찾으면 안 된다 —
"언탭" 은 신속 태그 설명에도 들어 있어서, 탭 단계를 통째로 지워도 통과한다(실제로 그랬다).
그 단계에만 있는 문장으로 찾는다.

학생은 **시킨 것을 실제로 해본다.** 코치가 오른쪽 클릭을 배우라고 하면 한 번 눌러보고,
그 뒤로 코치가 잔소리를 멈추는지("기본은 다 배웠어요" 로 넘어가는지) 확인한다.
그리고 코치가 "이 카드로 해보세요" 라고 예를 들면 그 카드가 화면에 있었는지 본다 —
카드 위의 태그 칩은 이름만 딱 적혀 있어서 정확히 일치로 찾는다. 카드 설명문에도
"비행 — 지상 생물은…" 처럼 그 낱말이 들어 있어서, 부분 일치로는 구별할 수 없다.

상세 상자를 찾을 때는 **어느 화면 것인지 좁힌다.** 전투와 덱 편집이 같은 이름의 상자를
갖고 있어서, 범위를 안 좁히면 비어 있는 쪽을 읽고 "설명이 없다" 가 된다(실제로 그랬다).

### 플레이해서 잡은 것 (2026-09-10)

| 무엇이었나 | 왜 그랬나 | 어떻게 고쳤나 |
|---|---|---|
| 오른쪽 클릭하면 태그 설명이 **두 번** 떴다 | 카드 설명문(`Sheet.luau`)에도 같은 문장이 적혀 있었다 | 설명문에서 태그 이야기를 걷어냈다. 규칙은 `KeywordText` 한 곳 |
| 항복 → 다시 하기 하면 안내가 **엉켰다** | "다시 하기" 는 같은 러너가 새 판을 여는 것이라 `Controller:start` 를 안 거친다. 코치가 지난 판의 마지막 단계에 머문 채 새 판을 맞았다 | 턴이 뒤로 가면 코치가 스스로 되돌아간다(`Tutorial:noticeNewMatch`) |

### 튜토리얼이 찾아낸 것 (2026-09-09)

학생이 같은 자리에서 계속 맴돌아서 잡힌 버그 둘이다. 둘 다 **화면이 켜준 것을
서버가 거부하는** 같은 종류였다 — 사람은 "눌러도 아무 일이 없다" 로 겪는다.

| 곳 | 무엇이었나 | 어떻게 고쳤나 |
|---|---|---|
| 공격준비 | 이미 공격을 선언한 생물이 계속 초록으로 켜졌다. 선언해도 **탭되지 않아서**(탭은 전투 해결 때 한다) `Combat.canAttack` 만으로는 안 걸러진다 | `Rules.hasDeclaredAttack` 을 만들어 서버 판정과 화면이 같은 함수를 본다 |
| 수비준비 | 이미 막힌 공격자가 계속 초록으로 켜졌다. `Combat.canBlock` 은 "막을 수 있는 종류인가"만 보고 배정 여부는 안 본다 | `Rules.canAssignBlockerTo` 로 같은 판정을 공유한다 (공격자 하나당 방어자 1명 — 확정 항목 6번) |

같은 김에 네 군데에 복사돼 있던 "지금 누가 두는가" 판정도 `Rules.whoActs` 하나로
합쳤다 (서버 · 클라이언트 · 터미널 클라이언트 · 계측 스크립트).

## ★ 기획서에서 확정이 필요한 항목

임의로 정하고 진행했다. **전부 `src/shared/Rules/Config.luau` 한 파일에서 바꿀 수 있다.**
바꿔도 테스트는 대부분 Config 값을 읽도록 짜여 있어 그대로 통과한다.

| # | 항목 | 현재 값 | 근거 / 대안 |
|---|---|---|---|
| 1 | 비행끼리 서로 방어 | **가능** (`flyingCanBlockFlying=true`) | 기획서 문자 그대로면 원거리만 비행을 막을 수 있어 비행이 사실상 무적이 된다. `false` 로 바꾸면 원문 그대로 |
| 2 | 원거리 직공 반올림 | **내림** (4→2, 5→2) | `"ceil"` 로 바꾸면 5→3 |
| 3 | 선공 1턴 드로우 | **생략** | 안 그러면 선공이 카드 우위 + 템포 우위를 동시에 가진다 |
| 4 | 같은 카드 최대 매수 | **4장** (코스트 카드 제외) | 기획서에 언급 없음 |
| 5 | 공격 선언 시 공격자 탭 | **탭됨** | 안 그러면 공격 후에도 방어가 가능해 탭이 자원 개념으로 기능하지 않는다 |
| 6 | 공격자 1명당 방어자 수 | **1명** | 다중 방어를 열려면 데미지 배분 순서 입력이 추가로 필요하다 |
| 7 | 공격준비 페이즈 상대 즉시시전 | **허용** | 기획서에 창이 없으면 "공격 선언에 대응"이 불가능해진다 |
| 8 | 수비준비 페이즈 **공격측** 행동 | **불가** | 기획서상 즉시시전 창은 "상대 메인/본인 메인/본인 수비"뿐 → 방어측이 마지막 발언권 |
| 9 | 생물 직접 겨냥 시 반격 | **탭된 생물도 반격** | 순수 트레이드. `false` 면 "탭시키고 잡아먹기"가 강해진다 |
| 10 | 빈 덱 드로우 | **패배** | 기획서에 없음 |
| 11 | 손패 상한 | **무제한** | 기획서에 없음 |
| 12 | 수비준비에 코스트 카드 소환 | **불가** | "1턴당 한 번"이 자기 턴 기준인지 불명확 |
| 13 | 멀리건 | **무료 1회 전체 교체** (`mulliganEnabled=true`) | 2026-09-09 사용자 확정. 코스트 24/60 이라 "코스트만 7장"·"코스트 0장" 이 실제로 나오고, 그 판은 아무것도 못 하고 끝난다. 벌칙(런던/파리)은 카드 풀이 넓어진 뒤에 얹는 게 순서 |
| 14 | 선공 결정 | **매치 시드로 동전 던지기** (`randomFirstPlayer=true`) | 좌석 1번 고정 선공으로 두면 "먼저 큐에 들어온 사람이 선공"이 되어 매칭 순서가 유불리가 된다. `false` 면 1번 좌석 고정 |

### 기획서 내부 모순 하나

신속 설명에 **"수비 페이즈에서 탭하여 소환할 수 있다"** 와,
수비준비 페이즈 설명에 **"신속 태그가 적용된 생물만 언탭하여 소환할 수 있다"** 가
서로 반대다. 후자(신속 = 언탭 등장 = 즉시 방어 가능)를 채택했다 —
그래야 "신속 = 즉시 행동"이라는 태그의 정체성이 일관된다.
