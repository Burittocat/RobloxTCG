### 서버 / 클라이언트 역할

상태의 주인은 서버 하나다. 클라이언트는 행동을 **요청**만 하고,
통과 여부는 서버의 `Rules` 액션 함수가 정한다.

그런데 클라이언트도 같은 `Rules` 모듈을 갖고 있다. 버튼을 켜고 끄고
초록 테두리를 칠할 때 `Rules.canPlayCard` · `Combat.legalAttackTargets` ·
`Combat.canBlock` · `Effects.validateTarget` 을 **서버가 부르는 것과 같은 코드**로 부른다.
그래서 "화면엔 켜져 있었는데 서버가 거부" 가 구조적으로 생기지 않는다.
서버가 그래도 다시 검증하는 건 클라이언트를 못 믿어서가 아니라, 같은 코드라 공짜라서다.

### 화면이 무엇을 말하는가

카드 게임에서 가장 자주 하는 실수는 "지금 내 차례가 아닌데 카드를 누르는 것" 이다.
그래서 **지금 누가 두는가** 를 세 군데에서 동시에 말한다.

| 어디 | 무엇 |
|---|---|
| 보드 테두리 | 내 차례면 초록, 상대 차례면 붉게. 카드를 보고 있어도 주변시로 들어온다 |
| 행동 바 배너 | `내 차례` / `상대 차례` — 턴 주인이 아니라 **행동권자** 다 |
| 상단 좌측 | `턴 3 · 상대 턴` — 턴 주인은 따로 표시한다 |

턴 주인과 행동권자를 나눠 적는 이유: 수비준비 페이즈에서는 **상대 턴인데 내가 둔다.**
하나로 합치면 그 순간 화면이 "상대 턴" 이라고 말하면서 내 입력을 기다리게 된다.

놓치면 그대로 오조작이 되는 카드 상태도 색 있는 칩으로 띄운다.

| 표시 | 뜻 |
|---|---|
| 기울어진 카드 + `탭됨` | 공격도 방어도 못 한다 (예전엔 4도 회전이라 사실상 안 보였다) |
| `공격 불가` | 이번 턴에 소환돼서 공격만 못 한다. **방어는 된다** |
| `공격` / `방어` 배지 | 전투 배정 결과 |
| 굵은 초록 테두리 | 지금 누를 수 있는 대상 |

### 대응 창 — 스택 상자를 눌러도 넘어간다

상대가 카드를 내면 스택이 열리고, **사람이 직접 넘겨야** 넘어간다
(자동 패스는 껐다 — 상대가 무엇을 냈는지 읽을 시간을 주려고).

예전에는 읽을 것이 보드 한가운데에 뜨고 누를 것([대응 패스])은 행동 바 오른쪽 끝에
있었다. 매번 눈과 손이 화면을 가로지르는 것이라 **상자에서 바로 넘기게** 하고,
행동 바의 버튼은 없앴다. 단축키 `P` 는 버튼과 무관하게 살아 있다.

**가운데 칸은 182px 뿐이다** — 설계 해상도 900 기준으로 보드 662 에서 위아래
(패널 92 + 필드 132 + 8) 를 빼고 남는 띠다. 처음에는 `스택` 라벨 · 카드 칩 ·
확인 버튼을 층층이 쌓았는데, 코치 말풍선(74)까지 겹치는 튜토리얼에서는 예산을 넘겨
**내 전장 줄 위로 흘러 소환물을 가렸다.** 그래서 읽을 것과 누를 것을 **상자 하나**에
합쳤다.

| 상태 | 상자에 적히는 것 |
|---|---|
| 평소 | `화염구 (상대) — 누르면 대응을 넘깁니다` |
| 한 번 누른 뒤 | `화염구 (상대) — 다시 누르면 넘어갑니다` |

**이름을 확인 문구로 갈아치우지 않는다.** 그 상자가 상대가 무엇을 냈는지 읽는 유일한
자리라, 이름을 지우면 읽으려던 사람이 무엇을 넘기는지 모르는 채 누르게 된다.
스택이 여럿이면 맨 위 것과 `외 N장` 을 적는다.

곧장 넘기지 않고 한 번 묻는 이유도 같다 — 읽으려고 누른 사람이 대응 기회를 잃으면
자동 패스를 끈 이유가 사라진다. 물어둔 것은 새 스냅샷(`onSync`) · [선택 취소] ·
실제 패스 · 새 판에서 거둔다.

가능한지는 `Controller:buttonStates()` 에 묻는다 — 튜토리얼 잠금이 거기 들어 있어서,
코치가 아직 안 켠 패스를 이 지름길로 앞질러 갈 수 없다.

**대상을 고르는 중일 때만 칩을 낱개로 편다.** 주문 파쇄(`SPL_NEGATE`)처럼 스택을
되받아치는 카드는 여럿 중 어느 것을 무효화할지 골라야 하기 때문이다. 그때는 잠깐이라
한 줄 더 써도 된다.

### 오른쪽 행동 바

조작이 전부 이 열에 있다. 그런데 **살아 있는 버튼은 보통 하나뿐이고** 나머지는 흐린
채로 자리를 지킨다(꺼진 버튼을 숨기지 않는 이유는 위치가 매번 바뀌면 누르기 힘들어서다).
그래서 "지금 눌러야 할 것" 이 덜 흐리다는 것만으로 구분됐다.

| 무엇 | 왜 |
|---|---|
| `[페이즈 종료]` 만 높이 52 | 이 열에서 제일 자주 누르는 **주 행동**이다. 크기는 꺼진 뒤에도 그대로라 자리가 흔들리지 않는다 |
| `[대응 패스]` 없음 | 스택 상자(보드 가운데)가 같은 일을 한다. 단축키 `P` 는 그대로 |
| `[항복]` 은 떼어서 맨 아래 | 되돌릴 수 없는 유일한 버튼인데 다른 것과 같은 크기로 붙어 있었다 |
| 최근 기록 두 줄 | 전체 기록은 `[로그]` 를 눌러야 열리는 덮개다. 코치가 "오른쪽 로그에 남아요" 라고 말하므로, **열지 않아도** 두 줄은 보여야 그 말이 참이 된다 |

**되돌릴 수 없는 일은 두 번 누른다.** 항복은 한 번 누르면 글자가 `정말 항복?` 으로
바뀌고, 그 상태에서 다시 눌러야 나간다. 다른 버튼을 누르거나 서버 상태가 바뀌면
물어둔 것은 거둔다 — 눌러놓고 잊은 항복이 나중에 나가면 안 된다. 스택 상자의
대응 넘기기도 같은 약속이다.

### 효과음

`src/client/UI/Sfx.luau` 한 곳에 **울림 목록**이 있다. 여덟 가지다 — 버튼(`click`) ·
거부(`deny`) · 내 차례(`turn`) · 대응 창(`stack`) · 부딪힘(`strike`) · 쓰러짐(`death`) ·
승(`win`) · 패(`lose`).

**에셋 ID 는 비어 있고, 그게 정상값이다.** 로블록스는 소리도 파일이나 URL 로 못 읽는다 —
업로드돼 모더레이션을 통과한 `rbxassetid://` 가 있어야 난다(`Theme.image.gold` 와 같은
사정). 비어 있으면 아무 일도 하지 않는다. 소리가 없다고 판이 멈추면 에셋을 붙이기
전까지 게임을 못 하게 되기 때문이다.

ID 는 Studio → 도구상자 → 오디오에서 무료 음원을 찾아 복사하거나, 직접 만든 소리를
크리에이터 대시보드 → 오디오로 올려 얻는다. **넣고 Studio 에서 한 번 들어봐야 한다** —
남이 올린 음원은 소유자만 쓸 수 있게 막혀 있는 경우가 많다.

**울리는 순간은 순수 함수가 정한다**(`Sfx.transitionCues`). 화면은 갱신마다 통째로 다시
그리므로 "지금 내 차례다" 같은 상태를 볼 때마다 울리면 소리가 끊이지 않는다 — 울려야
하는 것은 상태가 아니라 **넘어온 순간**이다. 그 판정을 화면에서 떼어냈기 때문에
룰 러너에서 그대로 테스트한다(때리는 시간표 `CombatTiming` 과 같은 이유다).

판이 끝나는 순간에는 **승패만** 운다. 끝은 내 차례로 돌아오며 오기도 하는데, 거기에
턴 소리가 겹치면 이긴 건지 진 건지가 안 들린다.

부딪힘과 쓰러짐은 연출과 **같은 순간**에 건다(`Battle:strikeAt` 의 충돌 콜백,
`Battle:playDeath` 의 지연 안쪽). 소리가 먼저 나면 맞기도 전에 아픈 것이 되고,
늦게 나면 무엇에 맞았는지 모른다.

### 글자 크기와 화면 배율

글자 크기는 위젯마다 정하지 않고 `Theme.text` 척도에서 고른다. 그러지 않으면
"여기만 10, 저기만 11" 이 쌓여서 전체를 키울 방법이 없어진다. 가장 작은 값이 12 인데,
로블록스는 창 크기가 제각각이고 텔레비전으로도 보기 때문이다.

레이아웃 치수(`Theme.size`)는 **일부러 안 키웠다.** 배치가 고정 픽셀이라 카드를 10px
키우면 보드 절반마다 20px 씩 먹어서 768px 창에서 가운데 영역이 음수가 된다.
대신 `Widgets.autoScale` 이 창 높이에 맞춰 화면 전체를 늘렸다 줄인다.

```lua
scale.Scale = clamp(뷰포트높이 / 900, 0.8, 1.5)
root.Size   = UDim2.fromScale(1 / scale, 1 / scale)   -- UIScale 이 곱한 걸 되돌린다
```

두 번째 줄이 핵심이다. UIScale 은 자식의 **scale 성분까지** 곱하므로 그것만 걸면
가로 전체를 차지하는 위젯이 화면 밖으로 나간다. root 를 1/배율로 잡아 상쇄하면
root 안쪽은 창 크기와 무관하게 **항상 세로 900 짜리 화면**이 된다 —
고정 레이아웃의 세로 예산이 창 크기에 따라 무너지던 문제가 사라지고,
큰 모니터에서는 같은 배치가 그냥 크게 보인다.

`tests/smoke.luau` 의 "화면 배율" 이 720 · 900 · 1440 세 창에서 이걸 확인한다.

### 겹쳐 막기

한 공격자를 **여러 마리가 함께 막을 수 있다. 인원 제한은 없다** — 막을 생물이 있으면
다 던질 수 있다. 방어자들은 저마다 공격력을 그대로
공격자에게 돌려주므로, 겹쳐 막으면 큰 놈도 잡힌다 — 그게 겹쳐 막는 이유다.

문제는 공격자의 공격력을 누구에게 얼마나 줄 것인가다. 정석은 **공격측에게 순서를
물어보는 것**인데, 그러려면 수비준비가 끝난 뒤에 입력 창이 하나 더 필요하다.
물어보지 않고 정하되 **공격측에 유리한 쪽**으로 고정했다.

    죽일 수 있는 방어자부터, 치사에 필요한 만큼만. 남으면 마지막에 몰아준다.

    4/2 원거리가 1/6 방벽 + 2/1 종자에게 막히면
      → 종자에게 1 (죽는다), 방벽에게 3 (안 죽는다)
      → 공격자는 1 + 2 = 3 을 맞고 죽는다

겹쳐 막을지는 **방어측이 이미 고른 것**이라, 배분까지 방어측에 유리하게 두면
겹쳐 막기가 언제나 이득이 된다. 그래서 배분은 공격측 편을 든다.

`Config.maxBlockersPerAttacker` 에 숫자를 넣으면 그만큼으로 제한된다(기본은 `math.huge`).

**AI 도 겹쳐 막는다.** 붙이는 조건은 둘이다.

1. 붙이면 **공격자가 죽는다** — 둘이 붙어도 못 잡으면 두 마리를 그냥 내주는 셈이다
2. 내가 잃는 것이 **한 마리 이하** — 두 마리를 잃고 하나를 잡는 건 손해다
   (막지 않으면 이번 전투로 죽는 상황이면 그때는 손해를 감수한다)

몇 마리가 죽는지는 `Combat.splitAmongBlockers` 로 **실제 배분 함수를 그대로 불러서**
재본다. 판정이 두 벌이면 AI 가 예상한 것과 실제 전투 결과가 어긋난다.

필요한 만큼 한 번에 다 붙인다. 한 마리씩 나눠 붙이면 "첫 마리만 붙고 두 번째가 막히는"
중간 상태가 생기는데, 그건 그냥 혼자 몸빵한 것이 된다.

### 전투 화살표

누가 누구를 공격하고 누가 그것을 막는지 **선으로 잇는다.** 공격은 빨강, 방어는 파랑.

Roblox 에는 선을 긋는 위젯이 없다. 가로로 긴 Frame 을 두 점의 중간에 놓고 각도만큼
돌리면 선이 되고, 끝점에 같은 각도로 돌린 글자(▶)를 얹으면 화살촉이 된다.

**매 프레임 다시 그린다.** 카드 위치는 레이아웃이 잡은 뒤에야 정해지고
(`AbsolutePosition`), 필드가 넘쳐 스크롤되면 그때그때 움직인다. 렌더 한 번에 그려두면
그 시점에는 좌표가 0 이고, 카드가 옮겨 가도 화살표만 제자리에 남는다.

**잰 거리를 배율로 나눠야 한다.** `AbsolutePosition` 은 진짜 화면 픽셀이고, 우리가 넣는
`Position`/`Size` 의 offset 은 루트의 `UIScale`(`Widgets.autoScale`)이 곱해진 뒤에 화면에
닿는다. 나누지 않으면 1080 화면(배율 1.2)에서 화살표가 카드에서 20% 씩 밀려나 아무 데도
안 닿는다 — 처음에 그렇게 내보냈다. 두께와 화살촉 크기는 원래부터 안쪽 좌표라 그대로 둔다
(배율과 함께 커져야 맞다).

스모크 테스트는 절대 좌표를 **직접 넣어 놓고** 한 프레임 뒤에 결과를 잰다. 하네스가
레이아웃을 안 굴려서 좌표가 전부 0 이기 때문인데, 덕분에 중점·길이·각도를 숫자로 확인한다.

화살표 판은 `Active` 를 켜지 않는다 — 입력을 가로채지 않아서 화살표 위로도 카드가 눌린다.

좌표는 Vector2 가 아니라 숫자 두 개로 다룬다. 벡터 연산을 쓰면 테스트 하네스의
Vector2 흉내에서 걸린다(거기엔 연산자가 없다).

### 좌석 — "나는 1번" 이 아니다

PvP 에서 나는 1번 좌석일 수도 2번일 수도 있다. 그래서 클라이언트에는 "내 좌석" 상수가
없고, 서버가 스냅샷에 실어 보내는 `viewerId` 가 그 자리를 대신한다.

```lua
self.me  = state.viewerId          -- Controller / Battle 이 매 렌더마다 채운다
self.foe = GameState.opponentOf(self.me)
```

화면도 좌석 번호로 만들지 않는다. 패널은 "아래칸/위칸" 으로 만들어두고, 누를 때
그 시점의 `self.me` / `self.foe` 를 가리킨다. 이게 어긋나면 2번 자리에 앉은 사람은
상대 패를 자기 손패로 보고 자기 생물을 상대 필드에서 찾게 된다 —
`tests/specs/net.luau` 의 "2번 좌석 시점" 이 그 대칭을 못 박아둔다.

서버 쪽도 같다. **어느 좌석의 행동인지는 클라이언트가 말하지 않는다.** `MatchRunner` 가
보낸 `Player` 로 좌석을 찾는다. 그래서 상대 좌석의 카드를 내는 요청은 만들 수조차 없다.

### 왜 Net 이 필요한가

Roblox 의 RemoteEvent 직렬화는 "1 부터 이어지는 배열" 과 "문자열 키 딕셔너리" 만
안전하게 옮긴다. 그런데 룰 상태에는 카드 인스턴스 id(숫자, 비연속)를 키로 쓰는
테이블이 여럿이다 — `state.cards[instanceId]`, `combat.blocks[blockerId]`,
구멍 뚫린 `targets[effectIndex]`. 그대로 실으면 **에러 없이 조용히** 모양이 바뀐다.

`src/shared/Net` 이 보내기 직전에 전부 배열로 펴고 받는 쪽에서 되돌린다.
Studio 를 켜야만 드러날 종류의 버그라서 `tests/specs/net.luau` 가
"스냅샷 안에 숫자 키 딕셔너리가 하나도 없다" 를 못 박아둔다.

### AI

`AI.act(state, playerId)` 는 **한 번에 한 수**만 두고 돌려준다. 호출자가 루프를 돌리므로
수와 수 사이에 연출/딜레이를 끼워넣을 수 있다. AI 는 상태를 직접 만지지 않고
사람과 똑같이 `Rules` 액션만 호출한다 — **AI 가 룰을 어기는 것이 구조적으로 불가능하다.**

테스트 스위트는 매번 AI 자기대국 5판을 끝까지 돌려 교착과 존 무결성을 확인한다.
단위 테스트로는 안 잡히는 "아무도 둘 수 없는 상태"가 여기서 걸린다.

`MatchRunner` 의 좌석은 **사람이거나 AI** 다. 좌석에 `player` 가 있으면 스냅샷을 쏘고
입력을 기다리고, `ai` 가 있으면 대신 한 수를 둔다. PvP 는 "AI 좌석이 하나도 없는 매치"
일 뿐이라 PvE 와 코드 경로가 갈라지지 않는다 — 갈라지면 둘 중 하나는 반드시 썩는다.

### 왜 Roblox 코드를 Studio 없이 테스트할 수 있는가

`tests/lib/RobloxEnv.luau` 가 `src/shared` 디렉터리를 읽어 Instance 비슷한 노드 트리를
만들고, `script` 와 `require` 를 주입한 환경에서 각 모듈을 실행한다.
**룰 엔진 코드에는 테스트를 위한 변환이나 분기가 한 줄도 없다** — Rojo 가 Studio 로
밀어넣는 파일과 테스트가 검증하는 파일이 바이트 단위로 같다.
