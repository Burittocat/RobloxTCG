# 카드팩과 컬렉션

가진 카드로만 덱을 짠다. 카드는 캠페인에서 번 골드로 팩을 사서 모은다.

---

## 카드팩과 컬렉션

| | |
|---|---|
| 규칙 | `src/shared/Collection/init.luau` — 순수 Luau. 팩 내용물 · 환급 · 잔액 · "이 덱을 짤 수 있나" |
| 저장 위치 | `DataStore` — 이름 `PlayerCollection_v1`, 키는 `user_<UserId>` (`src/server/CollectionStore.luau`) |
| 저장 모양 | `{ cards = { { id, count }, ... }, spent = 120, opened = 2 }` |
| 화면 | 시작 화면 **[카드팩]** → `src/client/UI/Shop.luau` |
| 테스트 | `tests/specs/collection.luau` (규칙) · `tests/smoke.luau` 의 "카드팩" 절 (배선) |

### 처음 받는 것

- **스타터 덱의 카드를 스타터 매수만큼** 가지고 시작한다. 그래서 [스타터 덱으로] 는 언제나 된다
- **코스트 카드는 무한**이다. 팩에서도 안 나온다 — 자원을 모으게 하면 덱을 못 짜는 사람이 생긴다
- 컬렉션이 생기기 **전에** 덱을 저장해둔 사람은 그 덱의 카드도 물려받는다. 안 그러면
  업데이트가 자기가 짠 덱을 빼앗는다. 물려받은 컬렉션은 처음 읽을 때 바로 저장한다

### 팩

| | 값 |
|---|---|
| 가격 | 100 골드 |
| 장수 | 5장 — 마지막 1장은 **희귀 확정** |
| 중복 환급 | 이미 4장 가진 카드는 일반 10 · 희귀 40 골드로 돌려준다 |

값은 `Collection.Pack` / `Collection.Refund` 에 있다. 기획서에 없는 값이라
[★ 확정이 필요한 항목](open-questions.md) 에 올려 뒀다.
**환급 합은 팩 가격보다 작아야 한다** — 다 모은 사람이 팩을 사서 골드를 벌면 안 된다.
`tests/specs/collection.luau` 가 이 부등식을 본다.

난수 시드는 서버가 뽑는다(`Lobby:buyPack`). 결과는 **저장에 성공했을 때만** 화면에 간다 —
카드를 보여줬는데 다음 접속에 없는 쪽이 더 나쁘다.

### 골드는 두 곳에 나눠 적는다

    잔액 = 캠페인 progress.gold (번 합)  −  collection.spent (쓴 합)

골드를 캠페인 저장소에서 빼고 카드를 컬렉션 저장소에 넣으면, 두 번째 쓰기가 실패했을 때
골드만 사라진다. 나눠 적으면 팩 하나 사는 것이 **컬렉션 저장소에 한 번 쓰는 것**으로 끝난다.
캠페인 목록 머리의 골드도 이 잔액을 보여준다.

### 가진 카드로 짰는지는 서버가 본다

| 어디서 | 무엇을 |
|---|---|
| 덱 편집 화면 | 가진 것보다 많이 못 넣는다. 안 가진 카드도 흐리게 남겨 둔다(무엇을 모을지 보이게) |
| `Lobby:saveDeck` | `Collection.covers` → `Decks.validateEntries` 순서로 둘 다 본다 |
| `Lobby:deckFor` | 판을 열 때 한 번 더. 걸리면 스타터 덱 |

**예약 서버(`Arena`)는 컬렉션을 다시 보지 않는다.** 저장할 때 이미 봤고, 거기서 다시
보려면 대전 서버가 저장소를 하나 더 읽어야 한다. 덱 저장소를 손으로 고치는 경로가
생기면 여기를 막아야 한다.

### 읽기에 실패하면

덱·캠페인과 같이 판은 열린다(스타터 컬렉션으로). 다른 점 하나 — **못 읽은 사람의
컬렉션은 저장하지 않는다.** 그 상태로 팩을 사서 쓰면 진짜 컬렉션을 스타터 + 한 팩으로
덮어쓴다. 그래서 그 접속 동안은 팩을 못 산다. 모양이 틀린 저장값도 덮어쓰지 않고 남겨 둔다.

## Robux 로 팩 사기

| | |
|---|---|
| 상품 ID | `src/shared/Products.luau` 의 `robuxPack`. **0 이면 버튼이 안 뜬다** — 아직 상품이 없다는 정상값 |
| 구매 창 | 카드팩 화면 [Robux로 열기] → 클라이언트가 `PromptProductPurchase` |
| 영수증 처리 | `Lobby:processReceipt` — 로비에만 건다. 대전 서버에는 구매 버튼이 없다 |
| 내용물 | 골드 팩과 같다(5장, 희귀 1 확정, 중복 환급). 골드는 안 쓴다 |

상품 만드는 법은 `Products.luau` 머리 주석에 있다(크리에이터 대시보드 → Developer Products).

**같은 영수증은 한 번만 준다.** Roblox 는 서버가 "처리했다" 고 답할 때까지 같은 영수증을
다시 보낸다. 그래서 처리한 영수증 ID 를 **카드와 같은 저장값**(`receipts`, 최근 100건)에
적는다 — 카드를 넣는 것과 영수증을 적는 것이 한 번의 쓰기라 중간 상태가 없다.

| 상황 | 답 |
|---|---|
| 저장까지 성공 | `PurchaseGranted` — 이 순서여야 한다. 먼저 답하고 저장이 실패하면 돈만 나간다 |
| 이미 처리한 영수증 | `PurchaseGranted` (아무것도 안 준다). NotProcessedYet 이면 영원히 다시 온다 |
| 저장 실패 · 컬렉션을 못 읽음 | `NotProcessedYet` — 다음에 다시 온다 |
| 결제한 사람이 이 서버에 없음 · 모르는 상품 | `NotProcessedYet` |

Robux 팩은 골드를 안 쓰는데 중복 환급은 주므로, `spent` 는 **음수가 될 수 있다**(= 받은 골드).

테스트: `tests/specs/collection.luau` 의 "Robux 팩"(규칙), `tests/smoke.luau` 카드팩 절의
영수증 테스트(배선 — 같은 영수증 두 번, 다른 서버로 옮겨 가서 다시 받기 포함).
스모크는 설정 파일의 상품 ID(0 이어도)로 가짜 영수증을 보낸다.

## 골드는 어디서 버나

| 어디서 | 얼마 | 제한 |
|---|---|---|
| 캠페인 첫 클리어 | 50 ~ 250 (합 660) | 스테이지마다 한 번 |
| 빠른 대전 승리 | 25 | **하루 4판**(UTC 날짜) · **4턴 미만에 끝난 판은 없음** |

PvP 규칙은 `Campaign.applyPvpWin`, 저장소에 적는 것은 `src/server/PvpReward.luau` 다.
게시된 게임(예약 서버의 `Arena`)과 Studio 같은 서버 매칭(`Lobby:startLocalMatch`)이 같은
함수를 부른다. 두 제한은 **부계정 농사**를 막으려는 것이다 — 계정 둘로 붙어 한쪽이
바로 항복하면 보상이 무한히 나온다. 하루 상한(100 = 팩 한 봉)이 총량을 막고, 최소 턴이
"들어오자마자 항복" 을 막는다. 진 쪽에는 아무것도 안 준다.

대전 서버는 진행도를 **저장된 값 위에서** 고친다(`CampaignStore:update`). 대전 서버의 캐시는
도착할 때 읽은 것이라, 그대로 덮어쓰면 다른 곳에서 쓴 값을 지운다.
진행도에는 하루 상한을 세는 `pvpDay` · `pvpWins` 가 붙는다. 없어도 되는 칸이라 옛 저장값도
그대로 통과하고, 저장소 이름은 바꾸지 않았다.

## 꾸미기 — 카드 테두리 · 카드 뒷면

**판에는 아무 영향이 없는** 겉모습이다. 종류마다 하나씩 낀다.

| 종류 | 어디에 보이나 |
|---|---|
| 테두리 (`frame`) | 내가 낸 카드(손패 · 필드). 상대 화면에서도 내 생물에 보인다 |
| 카드 뒷면 (`back`) | **상대 화면**의 내 패널에서 내 손패가 이 뒷면으로 보인다(TCG 슬리브와 같다) |

| | |
|---|---|
| 목록 · 가격 | `src/shared/Cosmetics/Frames.luau` · `src/shared/Cosmetics/Backs.luau` — 순수 테이블 (스모크 테스트가 Lune 에서 그대로 읽는다) |
| 규칙 | `src/shared/Cosmetics/init.luau` — 가졌나 · 끼고 있나 · 사기 · 끼기. 종류를 가리지 않는다 |
| 저장 | 컬렉션과 **같은 저장값**의 `cosmetics = { owned = { id, ... }, frame = id, back = id }` |
| 화면 | 시작 화면 **[꾸미기]** → `src/client/UI/Wardrobe.luau` (탭: 테두리 / 카드 뒷면) |
| 테스트 | `tests/specs/cosmetics.luau` (규칙) · `tests/smoke.luau` 의 "꾸미기" 절 (배선) |

### 등급 — 가격은 등급이 정한다

모든 꾸밈은 다섯 등급 중 하나다(`src/shared/Cosmetics/Grades.luau`). 꾸미기 화면 칸마다
등급이 **색 글자**로 붙는다.

| 등급 | 가격 | 테두리 | 뒷면 |
|---|---|---|---|
| 일반 | 0 | 기본 | 기본 |
| 희귀 | 100 골드 | 청동 | 밤하늘 |
| 레어 | 150 골드 | 물결 · 서리 | 불씨 |
| 에픽 | 250 골드 | 진홍 | 숲 |
| 고져스 | 400 골드 | 자수정 | 왕실 |

기본은 모두 가지며, 예전 카드 테두리 · 뒷면과 똑같은 값이다.

- 목록 파일에도 `price` 가 적혀 있다(스모크가 Lune 에서 그대로 읽으려고). 그 값은 등급의
  가격과 **같아야 하고** `tests/specs/cosmetics.luau` 가 본다 — 가격을 바꾸려면 `Grades.luau` 와
  목록 파일을 같이 고친다
- 카드 등급(일반 · 희귀 — 카드팩)과는 **다른 표**다. "희귀" 라는 이름만 같다
- "희귀" 와 "레어" 는 뜻이 같은 낱말이라 색으로 구분한다(초록 · 파랑)

**카드 앞면 바탕은 꾸미지 않는다.** 앞면 색이 생물 · 마법 · 코스트를 가르는 정보라, 꾸밈이
그걸 덮으면 판을 읽기 어려워진다. "스킨" 은 그래서 뒷면으로 했다.

### 종류를 늘리려면

1. `src/shared/Cosmetics/` 에 목록 파일을 하나 더 둔다 (`Backs.luau` 를 본뜬다)
2. `Cosmetics/init.luau` 의 `KINDS` · `KIND_NAME` 에 한 줄씩
3. `Lobby:dress` · `Arena:loadDeck` 이 좌석에 싣고, `MatchRunner:looks` · `Net.packView` 가 스냅샷에 싣는다
4. 화면 — `Wardrobe` 의 `TABS` 에 한 줄, 그리는 곳은 `CardView`

저장 · 사기 · 끼기 · 검증(`Collection.validate` · `Collection.copy`)은 손대지 않아도 된다 —
`cosmetics` 의 문자열 칸을 종류 이름 그대로 다룬다.

### 카드 데이터와 떼어 둔 레이어

꾸밈은 카드가 아니라 **사람에** 붙는다. 그래서 카드 정의에도, 룰 상태(`GameState`)에도
들어가지 않는다 — 룰 엔진은 꾸밈을 모른다.

    로비/대전 서버  좌석에 frame · back (Lobby:dress · Arena:loadDeck)
         ↓
    MatchRunner     스냅샷에 frames · backs = { [1] = id, [2] = id }  (MatchRunner:looks → Net.packView)
         ↓
    Battle          카드를 낸 사람(controllerId)의 테두리, 상대 좌석의 뒷면으로 CardView 가 칠한다

대전 서버(`Arena`)는 꾸밈도 덱처럼 **저장소에서 직접 읽는다.** 텔레포트 데이터로 나르면
클라이언트가 안 산 것을 끼고 들어올 수 있다.

### 테두리는 하이라이트를 이기지 못한다

선택·대상 하이라이트(두께 4)가 켜지면 테두리는 그동안 안 보인다. 테두리 두께는 늘 4 보다
얇다 — 꾸민 카드가 "누를 수 있는 카드" 처럼 보이면 그건 오조작의 원인이다.
`tests/specs/cosmetics.luau` 가 두께를 본다. 색도 하이라이트 색(초록 · 금색)을 피했다.

### 사기와 저장

- 사면 **바로 낀다.** 골드는 팩과 같은 잔액에서 나간다(`spent` 에 더한다)
- 테두리를 사는 것도 컬렉션 저장소에 **한 번 쓰는 것**이다 — 골드만 빠지고 테두리가 안
  들어가는 중간이 없다
- 컬렉션을 새로 만드는 곳은 전부 `Collection.copy` 로 통째 복사한 뒤 고친다. 칸을 하나씩
  옮겨 적던 때는 나중에 붙인 칸(영수증, 테두리)이 다른 경로에서 조용히 지워질 수 있었다
- 저장값이 없어진 테두리나 안 산 테두리를 가리키면 **기본으로 그린다.** 컬렉션 전체를
  못 읽게 하지는 않는다 — 카드까지 못 쓰게 되기 때문이다
