# 랭크와 프로필

빠른 대전(PvP)의 결과로 오르내리는 랭크, MMR 로 비슷한 실력끼리 붙이는 매칭, 그리고 내 랭크 ·
덱 · 꾸밈을 한 화면에 보는 프로필.

---

## 점수가 둘이다

| | 보이나 | 하는 일 |
|---|---|---|
| **랭크 점수** (`rankPoints`) | 보인다 | 이기면 +20, 지면 −10. 티어를 정한다 — 꾸준히 하면 오르는 "진도" |
| **MMR** (`mmr`) | **안 보인다** | 실력 추정치(Elo, 처음 1000 · k 32). 매칭에만 쓴다 |

하나로 합치지 않은 이유: 랭크를 Elo 로만 두면 실력이 멈춘 사람은 영원히 같은 숫자를 보고,
매칭을 랭크 점수로 하면 "많이 한 사람" 이 "잘하는 사람" 과 붙는다.
(2026-11-12 사용자 방향 — "승리로 얻는 점수로 랭크, MMR 기반 매칭")

MMR 은 **어느 화면에도 싣지 않는다.** 서버가 클라이언트로 보내는 어떤 값에도 없다 —
화면 코드에 안 오면 실수로라도 안 뜬다. 스모크 테스트가 시작 화면 · 프로필에 MMR 숫자가
없는지 본다.

| | |
|---|---|
| 규칙 | `src/shared/Rank/init.luau` — 순수 Luau. 티어 · Elo · 한 판 결과 적용 |
| 저장 | 캠페인 진행도(`CampaignProgress_v1`)에 `rankPoints` · `mmr` · `rankedWins` · `rankedLosses` — 없어도 되는 칸이라 옛 저장값 그대로 |
| 적는 곳 | `src/server/PvpReward.luau` — 판이 끝나면 두 좌석 모두 (골드 보상과 같은 입구) |
| 테스트 | `tests/specs/rank.luau` (규칙) · `tests/specs/matchmaking.luau` 의 "MMR 로 짝짓기" · `tests/smoke.luau` 의 "같은 서버 매칭" · "랭크 · 프로필" 절 |

## 티어

| 티어 | 랭크 점수 |
|---|---|
| 브론즈 | 0 |
| 실버 | 200 |
| 골드 | 500 |
| 플래티넘 | 900 |
| 다이아몬드 | 1400 |
| 마스터 | 2000 |

승률 50% 면 한 판에 평균 +5 라 브론즈→실버 40판, 다이아몬드→마스터 120판쯤이다.
랭크 점수는 0 아래로, MMR 은 100 아래로 안 내려간다. 티어를 넘으면 알림이 "승급!" · "강등" 으로 말한다.

## 짧은 판 — 농사와 도망을 둘 다 막는다

4턴(`Campaign.PvpReward.minTurns`)이 안 돼 끝난 판은 사실상 항복이나 이탈이다.

| | |
|---|---|
| 이긴 쪽 | **아무것도 적지 않는다** — 점수 · MMR · 승 수 전부. 부계정으로 바로 져 주는 농사를 막는다 |
| 진 쪽 | **그대로 내린다** — 질 것 같을 때 나가서 손해를 피하는 길을 막는다 |

**판을 떠난 사람에게도 패배를 적는다.** `MatchRunner` 가 좌석에 앉은 사람의 UserId 를 나가도
남겨 두고(`seat.userId`), `CampaignStore:change` 가 Player 없이 UserId 로 적는다.

## 두 사람의 변화량이 어긋나지 않게

변화량은 **판이 시작될 때의 MMR**(좌석의 `mmr`)로 계산한다. 끝난 뒤 저장소에서 다시 읽으면
먼저 적힌 쪽의 새 값으로 상대를 계산하게 되어, 한 사람이 얻은 만큼 다른 사람이 잃지 않는다.
적는 것은 저장된 값 위다(`UpdateAsync`) — 대전 서버의 캐시는 도착할 때 읽은 것이라.

| 판이 열리는 곳 | 좌석 MMR 을 읽는 곳 |
|---|---|
| 게시된 게임 (예약 서버) | `Arena:loadDeck` |
| Studio 같은 서버 매칭 | `Lobby:startLocalMatch` |

## MMR 로 짝짓기

`Matchmaking.plan` 에 `mmrWindow` 를 주면 MMR 차가 창 안인 사람끼리만 붙는다.

    창 = 100 + 10 × 기다린 초          (Matchmaking.MmrWindow)

- 오래 기다린 사람부터, 창 안에서 **MMR 이 가장 가까운** 사람과 붙인다
- 둘 중 **더 오래 기다린 사람의 창**을 쓴다 — 방금 온 사람의 좁은 창을 쓰면 넓혀 둔 것이 소용없다
- **상한이 없다** — 1분이면 ±700. 사람이 적은 시간에 고수 혼자 영원히 못 붙는 것보다 낫다
- MMR 이 없는 엔트리(옛 서버가 넣은 것)는 1000 으로 본다
- 두 백엔드(`Local` · `CrossServer`)가 같은 창을 준다 — Studio 에서 본 짝짓기가 실제와 같다

엔트리에 MMR 이 실린다(`Matchmaking.newEntry` 여섯째 인자). 로비가 큐에 넣을 때 진행도에서 읽는다.

## 화면

- **시작 화면** — 제목 아래 "빠른 대전 · 실버 245점" 을 티어 색으로. 접속한 순간에는 진행도를
  안 읽고(`CampaignStore:peek`) 먼저 띄운 뒤, 읽고 나서 다시 띄운다 — 시작 화면이 저장소를
  기다리지 않게
- **결과 알림** — 판이 끝나면 좌석마다 **한 줄**: "랭크 점수 +20 — 브론즈 20점 · 골드 25 (오늘 1 / 4판)".
  전투 화면의 알림 칸이 하나라 따로 보내면 뒤의 것이 앞의 것을 덮는다

## 프로필

시작 화면 오른쪽 위 **[프로필]** → `src/client/UI/Profile.luau` (`Lobby:openProfile`).

| 칸 | 무엇 |
|---|---|
| 랭크 | 티어(색) · 점수 · 다음 티어까지 남은 점수 · 전적과 승률 |
| 꾸밈 | 낀 테두리 · 뒷면 미리보기 (전투 · 꾸미기와 같은 함수로 그린다) |
| 덱 | 저장해 둔 덱. 코스트 카드는 장수만, 나머지는 코스트 · 이름 순 칩. 희귀는 금색 |
| 아래 | 모은 카드 · 캠페인 진도 · 골드 |

**보기만 한다.** 덱은 덱 편집에서, 꾸밈은 꾸미기에서 고친다 — 여기서도 고치게 하면 같은
판정이 두 곳에 생긴다. 저장한 덱이 가진 카드로 안 짜지면(컬렉션을 못 읽음 등) "지금은 스타터
덱으로 대전합니다" 를 붉게 띄운다 — 판이 열릴 때 실제로 그렇게 된다(`Lobby:deckFor`).

큐에 서 있는 동안은 [프로필] 버튼이 숨는다(메뉴와 같은 이유).

## 순위표

시작 화면 오른쪽 위 **[순위표]** → `src/client/UI/Leaderboard.luau` (`Lobby:openLeaderboard`).

| | |
|---|---|
| 저장 | OrderedDataStore `RankLeaderboard_v1` — 키 `user_<UserId>`, 값 랭크 점수. **정렬용 사본**이다(진짜는 진행도의 `rankPoints`) |
| 적는 곳 | `PvpReward.rank` — 랭크 점수가 바뀐 좌석만. 실패해도 판 결과는 그대로(다음 판에 맞춰진다) |
| 읽는 곳 | `src/server/LeaderboardStore.luau` — 위 50명, 30초 캐시(요청 한도). 이 서버에서 새로 적으면 캐시를 버린다 |
| 이름 | 이 서버에 있으면 Player.Name, 없으면 `GetNameFromUserIdAsync`. 못 찾으면 "플레이어 #id" |

- 내가 50명 안이면 내 줄을 초록 테두리로, 밖이면 아래에 "50위 밖 · 실버 245점"
  (OrderedDataStore 는 "이 사람이 몇 등" 을 물을 수 없다)
- 이름을 누르면 **그 사람의 프로필**(`Lobby:viewProfile`). 덱 · 골드 · MMR 은 안 나간다 —
  덱은 대전 상대에게 전략이 새는 정보다. 읽기만 하고 남의 캐시 · 저장값을 만들지 않는다
  (`CampaignStore:read` · `CollectionStore:read`). 한 사람이 1초에 한 번만 연다
- 프로필의 [뒤로] 는 온 곳으로(`backTo`)

테스트 하네스에 OrderedDataStore 와 `Players:GetNameFromUserIdAsync` 를 더했다
(`tests/lib/Roblox/init.luau` — `world.orderedStores` · `world.knownNames`).
